# 07 架构决策记录 ADR-001：清洗规则用 YAML 外置而非写死在代码

- 状态：已接受
- 日期：2026-10-14
- 决策者：项目组

## 背景
产线规则随工艺调整；写死意味着每次都要改代码+走发布，且易漏改

## 备选方案
A 硬编码（快但难维护）｜B YAML 外置（改配置即生效）｜C 数据库规则表（过度）

## 决策
**采用：B YAML 外置**

## 理由
改1行YAML即可；规则表本身就是文档；课堂对比实验可直接演示

## 后果
- 正面：换工艺口径只改 YAML 阈值/列名/策略，代码零改动；未知顶层键被记入 `warnings` 提示（不静默）
- 负面/代价：配置面变大后，写错阈值/键名的入口也随之增多
- 缓解：`Settings._validate()` 在 `load_config()` 阶段即抛 `ConfigError`（见 docs/03 §3
  `test_reversed_temp_threshold_raises`、`test_warn_above_danger_raises`），把错误挡在跑数据之前；
  v1.1 起同样启动校验外置的 PEP 8 分层线 `pep8_pass_rate`/`pep8_pass_rate_high`
  （必须落在 (0,100] 且 D 线≤B 线），档位判定线本身也是配置、不例外
