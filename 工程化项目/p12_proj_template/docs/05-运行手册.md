# 05 运行手册

> 项目：标准工程模板生成（03-P1.2）　　解释器：`/opt/anaconda3/envs/pp03/bin/python`

## 1. 环境准备
```bash
conda create -n pp03 python=3.12 -y
conda activate pp03
pip install -r requirements.txt      # 本项目仅依赖标准库（PyYAML 缺失时走内置 yaml_lite）
```
课堂说明：本机 pp03 **未安装** black/flake8/pylint/ruff/isort/pre-commit（离线装不了也无需装）——
生成器照样产出 `.pre-commit-config.yaml`，并在报告里如实标注"本次运行未调用这些工具"。

## 2. 运行
```bash
python run.py                        # 默认配置：生成 output/skeleton/ + report.txt + result.json
python run.py --config config/rules.yaml
python run.py --outdir output/
python run.py --quiet                # 只落盘，不打印结论
python -m pytest -q                  # 81 条用例 / 6 文件（不执行 git、不创建 venv、零子进程）
```

## 3. 配置说明（config/rules.yaml —— 与文件逐行一致，改配置不改代码）
| 键 | 本仓取值 | 含义 | 缺失时代码兜底（config.DEFAULTS） | 影响的层 |
|---|---|---|---|---|
| warn | 80.0 | 脚手架继承阈值（本项目逻辑未使用） | 80.0 | — |
| danger | 95.0 | 脚手架继承阈值（本项目逻辑未使用） | 95.0 | — |
| unit | "c" | 单位口径（继承键，本项目未使用） | c | — |
| seed | 7 | 随机种子（本流程无随机，保留以对齐口径） | 7 | — |
| topk | 3 | 检索/排序取前 k（继承键，本项目未使用） | 2 | — |
| project_name | pump-ops | 生成骨架的项目名（进 README/requirements/pyproject） | pump-ops | D |
| python_version | ">=3.10" | 写入生成 pyproject 的 requires-python | ">=3.10" | D |
| deps | numpy>=1.21、pandas>=1.5 | 生成 requirements.txt 的运行依赖，**必须逐行钉 `>=`/`==`** | [] | B |
| dev_deps | pytest>=8.0、black>=23.0、flake8>=6.0、pre-commit>=3.0 | 生成 requirements-dev.txt 的开发依赖（文件首行 `-r requirements.txt` 由模板固定） | 同本仓取值 | B |
| lint_tools | black、flake8 | `.pre-commit-config.yaml` 要声明的 hook 工具，同时是环境探测对象 | ["black","flake8"] | A |
| emit_pre_commit | true | 是否生成 `.pre-commit-config.yaml`；改 false → A 层立即未达标 | true | A |
| overwrite_existing | true | true=内容与模板不一致才重写；false=已存在即跳过（保留手改） | true | C/D |

> 改法示例（只动配置，不动代码）：把 `deps` 里的 `numpy>=1.21` 改成 `numpy` →
> 报告 B 层变成「运行依赖 1/2 条钉版本下限 → 未达标」；把 `emit_pre_commit` 改成 `false` → A 层未达标。
> 两种翻车场景都有对应用例守着（docs/04 §3）。

## 4. 输出物
| 文件 | 内容 |
|---|---|
| output/report.txt | 七段过程报告：输入口径 / 生成清单（文件盘点）/ 规范闸门环境探测 / **工单验收四档对照** / 分层达标 / 自检 / 结论与建议 |
| output/result.json | 结构化结果：files 字节清单、verify、layers 事实表、tiers、tier_lines、workorder_rows/workorder_tiers/workorder_lines/workorder_unmeasured/workorder_evidence（含 `skeleton_smoke` 真跑明细）、probes、config_echo |
| output/skeleton/ | 生成的 15 文件标准工程（README/.gitignore/.pre-commit-config.yaml/pyproject/双 requirements/run.py/src 3 件/tests 2 件/config/scripts 2 件） |
| output/skeleton/scripts/setup_venv.sh | C 层实物：`python -m venv venv` → 激活 → `pip install -r requirements.txt` → `pytest` → `git init` |
| output/skeleton/scripts/git_dev_branch.sh | B 层实物：`git branch dev` → `git checkout dev` → 小步 commit → `git merge --no-ff dev` |

## 5. 课堂执行顺序（工单逐条截图）
```bash
cd output/skeleton                       # ① 生成好的标准骨架
bash scripts/setup_venv.sh               # ② C 层：venv + 依赖 + 仓库（本项目的 pytest 不会替你执行它）
git add . && git commit -m "feat: 初始化标准工程模板"
git branch dev && git checkout dev       # ③ B 层：dev 分支，合并用 --no-ff
pip install -r requirements-dev.txt && pre-commit install   # ④ A 层：装上工具后钩子才真正拦截
```

## 6. 常见问题
| 现象 | 原因 | 处置 |
|---|---|---|
| `ModuleNotFoundError: yaml` | 离线环境无 PyYAML | 无需处理：`config.yaml_lite` 自动兜底 |
| 报告说"本机可导入 0/N" | 课程解释器没装 black/flake8 等 | 正常且如实；装上后同一行自动变 1/N、N/N |
| 想要 `pre-commit` 真的拦提交 | 只生成钩子文件不等于已安装已启用 | 在生成骨架里 `pip install -r requirements-dev.txt && pre-commit install` |
| 改了 `deps` 但生成树没变 | `overwrite_existing: false` 保留手改 | 改回 `true` 重新运行即按模板同步 |
| 报告"分层达标"某层显示未达标 | 配置与磁盘内容不一致 | 按该行数字定位（如"运行依赖 1/2"即某行没钉版本下限） |
| 「工单验收四档对照」某行写"→ 未达标" | 该行点名的实物（README/钩子/依赖下限/生成骨架的断言）在磁盘上不成立 | 看该行 ｜ 分隔的数字；对照节只认磁盘与真跑，改配置或补文件后复跑 |
| 「工单验收四档对照」每行都不写"达标" | 四行都还剩本机取不了证的子项（真激活 conda、真联网 pip、真触发 git 钩子、CI 未产出） | 这是**如实**，不是故障：按下一行「未取证项」清单在课堂/CI 侧补截图 |
| 中文乱码 | 控制台编码非 utf-8 | `set PYTHONIOENCODING=utf-8`（Windows）/ `export PYTHONIOENCODING=utf-8` |
