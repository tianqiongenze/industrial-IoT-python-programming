# 05 运行手册

## 1. 环境准备
```bash
conda activate pp03          # Python 3.12 + numpy 2.5.3 + scikit-learn 1.9.1 + joblib 1.6.0
pip install -r requirements.txt
python check_env.py          # 可选：课程环境自检（仓库根）
```
上游数据：课程根 `features.npy`/`labels.npy`（P2.2 产物）、教师包 `model_v1.joblib`、
P5 仓库 `../p55_warehouse_orm/output/warehouse.db`（先跑 p55 可得真实联动源）。

## 2. 运行
```bash
python run.py                         # 默认：加载→五步流→门禁→工件+manifest→教师自检→P5联动→压测(缓存)→报告
python run.py --serve                 # 起推理服务（config 端口 8899，阻塞；Ctrl-C 优雅停止）
python run.py --bench                 # 强制重新实测延迟/QPS（刷新 output/bench.json）
python run.py --no-bench              # 强制读 bench.json 缓存不重测（output/ 字节不变的验收口径；与 --bench 互斥，后者生效）
python run.py --predict '[…30个数值…]' # 单条特征离线预测（维度错/工件缺失→退出码 2）
python run.py --link-p5               # 只重跑 P5 联动回写
python run.py --export-onnx           # A 层 ONNX 导出探测（未装 skl2onnx 如实报告）
python -m pytest -q                   # 56 项全量测试（含 live HTTP 与 8 类错误探针实打）
```
curl 验收（先 --serve）：
```bash
curl http://127.0.0.1:8899/health
curl -X POST -H 'Content-Type: application/json' \
     -d '{"features":[ …30 个数值… ]}' http://127.0.0.1:8899/predict
curl -i -X POST -d '{"features":[1,2,3]}' http://127.0.0.1:8899/predict   # → 400
curl -i http://127.0.0.1:8899/nope                                        # → 404
```

| output/warehouse_diagnosis.db | P5 库副本+diagnosis 回写（每设备最新记录） |
| output/report.txt | D/C/B/A 分层报告：数据源注记、CM、对比表、GridSearch 留痕、联动表、A层可解释性 Top-k 表、**工单验收四档对照**（及格/良好/优秀/超优四行原文 + 未取证子项点名）、分层达标判定行、p95/QPS、ONNX 探测、决策矩阵 |

## 5. 可复现性口径
- 默认两次连续运行：`output/` 除 report.txt"生成时间"与 manifest 的
  `trained_at_utc`（显式版本时间戳）外**逐字节一致**（test_pipeline 自动化断言）。
- `--bench` 会刷新压测毫秒数与 QPS——刻意的"重新实测"动作，非默认路径；
  `--no-bench` 强制读缓存，两次 CLI 运行 output/ 字节不变的验收由
  test_tier_gates.py::test_no_bench_keeps_output_bytes_identical 取证。
- 墙钟红线：训练耗时 fit_ms 是墙钟实测值，**一律不写入 output/ 任何产物**
  （result.json 无 *_ms 训练键、report.txt 只引用 runtime/train_timing.json 路径行），
  故 PYTHONHASHSEED 不同的两次运行在 verify_local repeat 闸门下仍逐字节一致；
  可解释性 Top-k 并列用 zlib.crc32(特征名) 破序，杜绝 hash() 随机漂移。
- features.npy 缺失时自动切 seed=42 合成替代源，报告首行注明来源（"真实数据"vs
  "合成替代源"），不静默。

## 6. 常见问题
| 现象 | 原因 | 处置 |
|---|---|---|
| 端口占用 OSError 98/10048 | 8899 被占 | 改 rules.yaml port；测试用 port=0 由内核分配 |
| 400 detail="特征维度 X 与模型契约 30 不符" | 入参非 30 维 | 按 FEATURE_NAMES 列序补齐（report.txt 数据段有清单） |
| --predict 退出码 2 | 未训练/工件缺失或入参非法 | 先 `python run.py`（训练一次即可，后续 --serve/--predict 复用工件） |
| 教师包加载告警 | 跨 sklearn 版本 pickle | 告警已如实转录进报告 [D层]，不影响推理结果核对 |
| ONNX 不可得 | 离线环境未装 skl2onnx/onnxruntime | 报告如实说明；装上后 --export-onnx 自动导出+延迟对比 |
