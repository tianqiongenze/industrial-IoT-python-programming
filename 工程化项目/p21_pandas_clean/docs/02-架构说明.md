# 02 架构说明（TOGAF 四域视角）

> 项目：Pandas 数据清洗管道

| TOGAF 域 | 本项目答案 |
|---|---|
| 业务架构 | 把'跑一次就扔'的清洗脚本变成可维护、可复现的数据管道 |
| 数据架构 | 原始CSV → 规则化清洗 → 质量分 + 前后对比留痕 |
| 应用架构 | core 为规则表驱动清洗（纯函数）；io_utils 负责 CSV 读写 |
| 技术架构 | Python 3.12 + conda pp03；pandas；pytest |

## 分层与模块职责
| 模块 | 职责 | 关键接口 |
|---|---|---|
| `core.py` | 规则表驱动清洗 + 质量分 | `RULES/clean()/quality()` |
| `io_utils.py` | CSV 原子读写 | `read_csv_rows()/write_csv_rows()` |

## 依赖方向
```
run.py  →  pipeline  →  core（纯函数，零依赖）
               ↓           ↑
            io_utils ←── report
               ↑
            config（YAML 驱动）
```
**规则**：下层不得反向依赖上层；`core` 不 import `io_utils`（保持可单测）。

## 关键质量属性
- **可测试性**：core 为纯函数 → 单测无需 mock 文件系统
- **可配置性**：阈值全部外置 YAML
- **可复现性**：种子固定于配置
