# 02 架构说明（TOGAF 四域视角）

> 项目：多源数据采集中枢

| TOGAF 域 | 本项目答案 |
|---|---|
| 业务架构 | 设备数据可靠汇聚为集团级数据底座 |
| 数据架构 | 各源寄存器原值 → ÷scale 还原 → batch；两条对账恒等式 Σ批次=Σ单条、调用=成功+丢弃+重试 |
| 应用架构 | core 提供 transport 可注入的重连采集/还原/对账/计数纯函数；pipeline 用同一份故障注入跑「不重连」「指数退避重连」「零丢弃（上限抬到最严重故障）」三条链路，前两条产出课堂 D/C/B/A 分层达标证据，第三条产出工单验收四档对照（原文取自 `pipeline.WO_ROW` 单源常量） |
| 技术架构 | Python 3.12 + conda pp03；零依赖可跑（pymodbus 可选）；pytest |

## 分层与模块职责
| 模块 | 职责 | 关键接口（真实函数名） |
|---|---|---|
| `config.py` | YAML → Settings；零 PyYAML 环境自动降级 | `load_config()` `yaml_lite()` `Settings.from_dict()` |
| `core.py` | 纯逻辑：断线重连、批量采集、还原、对账、计数自洽 | `LinkDown` `new_stats()` `merge()` `read_retry()` `collect()` `restore()` `reconcile()` `sleep_with()` `rate()` `check()` |
| `io_utils.py` | JSON/文本原子落盘 | `write_json()` `write_text()` |
| `report.py` | 等宽文本报告渲染与落盘 | `render()` `save()` |
| `pipeline.py` | 双链路编排 + 分层达标判定 | `run(cfg, out_dir)` |
| `cli.py` | 命令行入口（run.py 与 console script 共用） | `build_parser()` `main(argv)` |

## 依赖方向
```
run.py → cli ─┬→ config（YAML 驱动）
              └→ pipeline ─┬→ core（纯函数，零依赖）
                           ├→ report → io_utils
                           └→ io_utils
```
**规则**：下层不得反向依赖上层；`core` 不 import `io_utils`（保持可单测）；
读数与故障由 pipeline 注入的 `transport(src, slot, attempt)` 提供，`core` 不碰真实链路。

## 关键质量属性
- **可测试性**：core 为纯函数且 transport 可注入 → 单测无需 mock 文件系统，也不必真连 PLC
- **可配置性**：阈值全部外置 YAML
- **可复现性**：读数由 zlib.crc32 确定性生成、计数全部由配置推导（不含墙钟），二次运行逐字节一致
