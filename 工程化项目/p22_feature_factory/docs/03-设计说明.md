## 2. 核心算法/规则
设计核心是**把"特征算得对"变成可对账的恒等式，把"以向量化为主"变成可扫描的静态闸门**；
下面每个数字都来自本次 `output/report.txt` / `output/result.json`，重跑即可证伪。

**2.1 特征注册表是唯一真源**
`core.TIME_FEATS`(10) + `FREQ_FEATS`(15) + `STAT_FEATS`(5) 拼成 `PRIMARY_FEATS`(30)，
`DERIVED_FEATS`(5) 由主特征列组合（`d_impact=crest×kurtosis_excess`、`d_severity=rms×spec_centroid`
等），`extract()` 返回 `PRIMARY+DERIVED` 共 35 列。`META` 给每个名字挂
「公式/物理含义/单位/参考量程」，`feature_dict_rows()` 再补「族」与本次实测范围 ⇒
特征字典 35 条 × 7 列（工单工程要求第 2 条「五列规范」）。列数由 `_stack()` 与
`build()` 双重硬校验（`features.primary` 与 `len(PRIMARY_FEATS)` 不等即抛错），
"文档一套、代码一套"进不了流水线。

**2.2 一次 FFT 的共享底座**
`Ctx.__init__` 一趟算完所有公共量：`spectrum()` 先 `keepdims` 去直流、再 `|rfft|·2/N`、DC 置零
（工单避坑第 1 条）；二阶/三阶/四阶中心矩用 `d2=dev*dev` 显式相乘（不用 `dev**3/**4`），
`rms=√(m2+mean²)` 免二次遍历；15 个频域特征共享同一份 `freqs/amp/power`，前 3 大谱线用
`argpartition`（`features.peak_orders=3`）取。信息熵用「全局桶号 + `bincount`」做向量化直方图。
信号合成 `make_signals()` 走**功率守恒**口径：1× 与 2× 共享线谱功率 `signal.tone_power=0.008`
（`A1=√(2P(1−u))`、`A2=√(2P·u)`），每窗独立 looseness/初相/噪声底 ⇒ 时域幅值特征不是判别捷径，
证据只能落在 16Hz 的 `a16` 上：实测重要性第 1 名（0.1851），US-02 判定达成。

**2.3 恒等式对账（7 条）**
`identity_devations()` 用真实产出的列回算：`var=std²`、`rms²=mean²+var`、
`kurtosis_excess=kurtosis−3`、`crest=peak/rms`、`shape_factor=rms/abs_mean`、`cv=std/|mean|`
六条严格恒等（容差 `IDENTITY_TOL=1e-10`，本次 1000 窗最大偏差 5.6e-17），另加 Parseval
口径 `spec_energy≈2·var`（`PARSEVAL_TOL=5e-3`，本次偏差 7.4e-04）。谁把某一列改成
"另算一遍"的写法，这里当场露馅；缺列直接抛 `FeatureError`，不静默放行。

**2.4 标准化与防泄漏（B07）**
`train_test_idx()` 按类分层切分（`model.test_size=0.3`、seed 固定 ⇒ 训练 700 / 测试 300），
`zscore_fit()` **只吃训练段**估计 μ/σ（常数列 σ→1 防除零），`zscore_apply()` 对全量只做变换；
`scaler.json` 落 μ/σ 与 `leak_guard` 文字。落盘契约：`features.npy` 是 1000×30 的**原始量纲**
主特征，标准化留给下游按同一份 scaler 做。随机森林（200 树、`min_samples_leaf=2`、
`random_state=seed`）在标准化后的训练段拟合、测试段评估：accuracy=1.0000、f1=1.0000、
轮廓系数 0.4550（标准化主特征实测）。`model.cv_folds` 仅由 `_validate()` 守口径（≥2），
当前流水线未做交叉验证。

**2.5 相关矩阵去冗余（A 层）**
`corr_matrix()` → `drop_redundant(R, names, keep_idx, threshold)`：`keep_idx` 是**优先级顺序**
（`redundancy.keep=importance` ⇒ RF 重要性降序入场；`=rank` ⇒ 清单顺序），先入场者占位，
后来者逐个与"已保留列"比 |r|，**|r| ≥ 阈值即判冗余**（含等号，`redundancy.corr_threshold=0.95`），
并记录被谁挤掉（`kept` 赢家）与 |r| 数值 ⇒ 可复核的取舍说明。本次主特征域 30 列两两共 435 对，
其中 23 对达阈值 ⇒ 剔除 11 个、保留 19 个（保留＋剔除＝30；衍生 5 列由主特征组合，故不再剔），
全表 35×35 口径 28 对；严格恒等 |r|=1 的对有 1 对（`kurtosis↔kurtosis_excess`）——
恒等式对至多留一个，后入场者必被判冗余。

**2.6 AST 向量化闸门（C 层）**
`vector_check.scan()` 按 `vectorization.targets`（config 项，可增删）逐个解析 `core` 的
**12 个特征函数**：`Ctx.__init__`、`spectrum`、`_top3`、`Ctx.amp_at`、`Ctx.band_power`、
`_time_feats`、`_freq_feats`、`_stat_feats`、`_stack`、`extract_primary`、`extract_derived`、
`extract`。循环按**迭代对象**定性：命中 `registry_names`（`TIME_FEATS`/`PRIMARY_FEATS`/`cols`/
`names`… 即"迭代特征名注册表"，次数＝特征数 35，与样本量无关）算允许；命中 `sample_names`
（`X/x/y/F/Z/sig/window`… 即"迭代样本轴"）或来路不明对象算违规。本次 0 处违规、
2 处注册表级循环（`_stack` 的 `enumerate(cols)`、`extract_derived` 的
`enumerate(PRIMARY_FEATS)`）⇒ 判达标。`test_ast_count_equals_dis_for_iter_count` 把每个函数的
AST 计数与教师版 `dis.get_instructions()` 的 FOR_ITER 计数逐函数对齐（AST 口径＝字节码口径）；
`enabled=false` 或清单里的函数在源码找不到 ⇒ `status` 为 `disabled`/`config_drift`、`ok=False`，
C 层直接判未达标——闸门不许空转。

**2.7 图表与中文字体**
`plot_boxplot()`（重要性 Top6 × 两类并排，B 层证据）与 `plot_corr_heatmap()`（|r| 矩阵，
A 层决策证据）走 matplotlib `Agg` 后端；`use_cjk()` 运行时按 `CJK_FONT_CANDIDATES`
（PingFang SC / Noto Sans CJK SC / SimHei …）探测本机字体，命中才用"正常/磨损"等中文标签，
否则整体退回英文标签，避免图上全是豆腐块。无 matplotlib 时两个函数返回 `None`，
A 层因热力图缺失判未达标，不会假装出图。

**2.8 四级闸门与墙钟隔离**
`ledger()` 的 `tiers` 四个布尔全部由运行期实测推出：D＝六条严格恒等式与 Parseval 同时成立
＋特征矩阵全有限＋有样本；C＝主特征数与分组名单自洽（无重名、频域 15）且 AST 闸门 `ok`；
B＝特征计算 ≤ `perf.target_ms` 且特征字典物理含义零空白；A＝热力图已落盘＋
保留∪剔除恰为 30 个主特征＋每个剔除项都带 `kept` 赢家与 |r| 证据。
四行达标要求文字逐字取自教师版 W04 notebook cell-0 的「达标要求」列（`pipeline.TIER_REQ`），
与工单《验收标准》表（及格(D)=「30特征计算正确；向量化为主；标准化正确；PEP 8≥75%」、
良好(C)=「1000样本<100ms；特征字典含物理含义」、优秀(B)=「<50ms；广播运用充分；箱线图输出；
文档完整」、超优(A)=「优秀+衍生特征5个+相关性特征选择(去冗余)」）**存在一级档位差**：工单 D 档
的内容对应代码 C 档、工单 C 档对应代码 B 档，代码 D 档「跟做示例跑通第①个留白(var)」与工单 B 档
「<50ms＋箱线图」在另一套口径里各无对应行。**两套口径现在各自独立取证，互不顶替**：
`TIER_REQ` 四行判课堂阶梯，`WO_ROW` 四行（`pipeline.WO_ROW` 逐字照抄工单原文）判工单阶梯，
后者落在报告 §8.5「工单验收四档对照」——`perf.excellent_ms`（50ms）在那里就是工单优秀(B) 的
档线（课堂阶梯里没有一行用它），超优档按工单原文"优秀+…"把优秀档的实测项当前置条件。
测不到的子项（标准化口径、PEP 8 子集、广播写法）在行内以「未实测项：…」点名，不参与判档。
墙钟实测值（`best_ms` / `all_ms` / `load_ms`）**只**写 `io.out_timing_json` 指向的
`../runtime/timing.json`（`output/` 之外），`report.txt` 与 `result.json` 内不出现任何时长数值
⇒ 换 `PYTHONHASHSEED` 重跑 `output/` 逐字节一致（用例
`test_measured_ms_lands_in_runtime_not_output`、
`test_output_is_byte_identical_across_two_hash_seeds`）。

## 3. 异常处理策略
| 异常 | 触发场景 | 处理 | 对应测试（真实节点名） |
|---|---|---|---|
| FileNotFoundError | `config/rules.yaml` 缺失 | `load_config()` 抛出并提示路径，不静默改用默认值 | `tests/test_config.py::test_missing_config_raises` |
| `ConfigError`（`config.py` 自定义，是 `ValueError` 子类） | 阈值顺序颠倒（`warn ≥ danger`）、`corr_threshold` 越出 (0,1)、`redundancy.keep` 非 importance/rank、`excellent_ms ≥ target_ms`、AST `targets` 为空或注册表名单与样本轴名单冲突等（`_validate()` 共 30 条 `raise`） | 启动即校验并拒绝，一行数据都不跑 | 无专列用例（出厂配置合法）；`test_config.py::test_load_default_config`、`::test_settings_defaults_fill` 断言出厂 `warn < danger`，`test_vectorization.py::test_turning_the_gate_off_by_config_leaves_c_layer_unmet` 走 `from_dict()` 的校验入口 |
| `FeatureError`（`core.py` 自定义，是 `RuntimeError` 子类） | 空矩阵、窗口 `L<8`、输入含 NaN/Inf（`Ctx` 入口拦截）；`make_signals` 的 `n<2`、`fault_ratio`/`impact_rate` 越界、噪声上下限颠倒 | 立即抛错并点名口径，**不返回"空结果＋告警"** | `tests/test_core.py::test_extract_rejects_bad_input` |
| `FeatureError` | 特征矩阵算完仍含 NaN/Inf；列数与约定不符（`_stack`）；恒等式对账缺列 | `_assert_finite()` 列出坏列名；`identity_devations()` 报缺列 | `tests/test_drop_redundant.py::test_identity_devations_helper_agrees_with_manual_checks` |
| `FeatureError` | `features.primary` 与 `len(PRIMARY_FEATS)` 不一致；clean.csv 切不出窗口 | `build()`／`signals_from_frame()` 启动即拒绝，禁止文档与代码两套口径 | 由 `tests/test_tier_gates.py` 走真实 `build()` 的 12 例共同覆盖（该分支在通路上） |
| AST 闸门判违规／漂移 | 逐样本 for/while/推导式、迭代来路不明对象；或 `targets` 点名的函数在源码找不到 | `status` 为 `violation`／`config_drift`、`ok=False`，`detail_lines()` 点名到特征名，C 层判未达标 | `tests/test_vectorization.py::test_injected_per_sample_loops_are_flagged_loudly`、`::test_missing_target_is_reported_as_drift_not_pass` |

## 4. 命名与代码规范
- PEP 8；`snake_case`（函数/变量）、`PascalCase`（类）、`UPPER_CASE`（常量）
- docstring 三件套：做什么 / 参数 / 返回
- 单元函数 ≤40 行，超过则拆分；实测例外三类：校验规则表 `config.Settings._validate()`（78 行）、
  数据口径装配 `core.make_signals()`（48 行）与线性装配／报告行拼装的
  `pipeline.build()`（70 行）、`pipeline.result_json()`（68 行）、`pipeline.ledger()`（241 行）——
  拆开反而打断证据链，其调用的每个算法步骤在 `core` 里仍保持 ≤40 行
