# 02 架构说明（TOGAF 四域视角）

> 项目：Python 五题闯关（工单 P1.1）　对应代码：`src/exercise_five/`

| TOGAF 域 | 本项目答案 |
|---|---|
| 业务架构 | 新员工入职测评：吴工按五题结果定岗定层，**定档权威是工单 P1.1 分层表**（及格 D / 良好 C / 优秀 B / 超优 A），达标线由 `selfcheck.tier_gate()` 逐条实测判定并写进报告；课堂跟做四阶降级为"保底自检"，不占工单字母 |
| 数据架构 | `config/rules.yaml` 是唯一数据契约（阈值/样例/设备清单/ID 宽度/扫描上限/工单四档线值 `pep8_pass_rate_d`、`pep8_pass_rate_b`、`d_min_correct`、`c_min_correct`、`b_min_correct`、`naming_meaningful_rate`、`tests_per_question_min`）；`output/result.json` 是下游取数契约（含逐档 `tiers`） |
| 应用架构 | 单入口 CLI → pipeline 编排 → exercises（一题一函数）→ core（业务判定）→ selfcheck/stylecheck/testmap/notes 四个度量器 |
| 技术架构 | Python 3.12（conda `pp03`）+ pytest 9.1.1 + PyYAML 6.0.2（缺失时降级内置 `yaml_lite`）；课堂未装 pylint/flake8/black/pre-commit，故规范由标准库实现的 `stylecheck` 实测 |

## 依赖方向
```
run.py → cli → pipeline → {exercises → core, selfcheck, stylecheck, testmap, notes}
                         → report / io_utils（落盘）
            config（YAML → Settings）→ 被上面各层读取
```
**规则**：下层不反向依赖上层；`core` 不 import `io_utils`/`config`（保持纯函数可单测）；
`pipeline` 是唯一知道"文件写在哪儿"的模块。

## 关键质量属性与实现手段
- **可测试性**：core 纯函数 → 单测无需 mock 文件系统；`Registry`/`PLC` 的状态都靠入参构造。
- **可配置性**：阈值/设备/扫描上限/topk/seed/工单四档线值（及格 PEP 8 `pep8_pass_rate_d`、优秀 `pep8_pass_rate_b`、题数线 `d/c/b_min_correct`、命名线 `naming_meaningful_rate`、每题用例线 `tests_per_question_min`）全部外置，未知顶层键报"死配置"告警（`config.py:194` 起）。
- **可复现性**：报告无时间戳、笔记无时间戳、样例按配置重建、抽签用 `seed` 取模（`notes.py:78`）。
- **诚实性**：外部工具缺失时 `pylint_score()` 返回 `score=None` 并在报告里写"不可用"，不用内置百分比冒充 pylint（`stylecheck.py:70`）。
