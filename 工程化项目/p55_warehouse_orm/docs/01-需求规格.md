## 1. 范围
把 P4 采集数据沉淀为可查询的数据仓库：4 表 ER 设计（设备/测点/采集记录/告警事件）
+ SQLAlchemy 2.x 声明式 ORM（DeclarativeBase/Column/ForeignKey/relationship/Session）
+ 外键约束强制（孤儿记录被库拒绝）+ P4 缓冲数据批量入库（每批 100 条、逐批事务提交）
+ KPI 统计与故障溯源查询（JOIN+GROUP BY+聚合、Top-K、按小时聚合、窗口函数环比、四表 JOIN 聚合）
+ 联合索引 idx_dev_ts(point_id, ts) 与 EXPLAIN QUERY PLAN 前后计划形态取证
+ 工单四档（及格/良好/优秀/超优）逐条实测判定 + 导出 P3 仪表盘可读的交接 CSV 形成闭环。
数据库用 SQLite（零安装），确定性证据只落本项目 output/，墙钟实测值落 runtime/。

## 5. 非功能需求
| ID | 类别 | 要求 | 验证方式 |
|---|---|---|---|
| NF-1 | 可复现 | 固定随机种子；`hash_of()` 代替内置 `hash()`；sqlite 文件先删后建；墙钟值不进 output/ —— 任意 PYTHONHASHSEED 下两次运行 output/ 除报告时间戳行外逐字节一致 | test_pipeline.py::test_pipeline_two_runs_identical_except_timestamp、test_tier_gates.py::test_two_runs_agree_on_tiers_and_output |
| NF-2 | 可移植 | 课程环境 pp03（Python 3.12 + SQLAlchemy 2.1.3 + SQLite 内置） | 换机运行 |
| NF-3 | 可配置 | 库 URL/阈值/批量/基准行数/替代源行数/统计查询门槛/N+1 加载策略/交接文件路径共 15 个键全在 config/rules.yaml 且被代码读取 | 改配置不改代码 |
| NF-4 | 可测试 | pytest 58 项覆盖建表/外键/关系/查询/批量/基准/溯源/聚合/交接/端到端/分层闸门/墙钟红线 | `python -m pytest -q` |
| NF-5 | 可证伪 | 每一级闸门都能只改配置（不改代码）判为未达标；禁止无证据的"达标" | test_tier_gates.py 5 个 falsifiable 用例 |
| NF-6 | 跨项目契约 | P5 导出列名/时间格式与 p33_kpi_cockpit 的 `data_source.CANON`、`_DT_FORMATS` 对齐；P5 不伪造 P3 的合成列 | test_queries.py::test_p3_handoff_readable_by_p3_cockpit |

## 6. 接口约束
- CLI：`python run.py [--config CONFIG] [--outdir DIR] [--quiet]
  [--query avg-vib|top-alarms|hourly|window|all] [--index-bench] [--buffer PATH]`
- 配置：`config/rules.yaml`（键表见 docs/05）
- 输出（确定性证据）：`output/warehouse.db`（四表+索引）、`output/report.txt`、
  `output/result.json`、`output/p3_dashboard_handoff.csv`（A 层 P3 交接文件）
- 输出（墙钟实测）：`runtime/bench.json`（索引前后毫秒/提速倍数/慢查询中位毫秒）、
  `runtime/bench.db`（基准副本库，不污染业务库）——`runtime/` 已在 .gitignore
- 下游接口：`cd ../p33_kpi_cockpit && python run.py --source csv --csv ../p55_warehouse_orm/output/p3_dashboard_handoff.csv`
