# 02 架构说明（TOGAF 四域视角）

> 项目：标准工程模板生成

| TOGAF 域 | 本项目答案 |
|---|---|
| 业务架构 | 把'新人第一天的手工建目录'变成一键规范骨架，减少不规范代码的源头 |
| 数据架构 | 项目名/依赖清单/起始配置 → 生成 10 个标准文件 |
| 应用架构 | 模板文件用居中的常量表管理；新增文件=改表，不改逻辑 |
| 技术架构 | Python 3.12 + conda pp03；仅标准库；pytest |

## 分层与模块职责
| 模块 | 职责 | 关键接口 |
|---|---|---|
| `core.py` | 模板定义 + 生成器 + 自检 | `FILES()/ensure()/verify()` |
| `io_utils.py` | 原子写 | `write_text()` |

## 依赖方向
```
run.py  →  pipeline  →  core（纯函数，零依赖）
               ↓           ↑
            io_utils ←── report
               ↑
            config（YAML 驱动）
```
**规则**：下层不得反向依赖上层；`core` 不 import `io_utils`（保持可单测）。

## 关键质量属性
- **可测试性**：core 为纯函数 → 单测无需 mock 文件系统
- **可配置性**：阈值全部外置 YAML
- **可复现性**：种子固定于配置
