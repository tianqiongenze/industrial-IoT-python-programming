# 02 架构说明（TOGAF 四域视角）

> 项目：Pandas 数据清洗管道

| TOGAF 域 | 本项目答案 |
|---|---|
| 业务架构 | 把'跑一次就扔'的清洗脚本变成可维护、可复现的数据管道 |
| 数据架构 | 原始CSV → 规则化清洗 → 质量分 + 前后对比留痕 |
| 应用架构 | core 为七步清洗纯函数（阈值由 YAML 驱动、非代码内规则表）＋工单四档判定；io_utils 负责 CSV/JSON/文本读写；stylecheck 落地内置 PEP 8 子集检查；pipeline 只做编排与证据采集 |
| 技术架构 | Python 3.12 + conda pp03；pandas；pytest |

## 分层与模块职责
| 模块 | 职责 | 关键接口（真实函数名） |
|---|---|---|
| `config.py` | YAML → Settings ＋启动校验（含 PEP 8 分层线 0–100 且 D 线≤B 线；缺 PyYAML 降级 `yaml_lite`） | `load_config()/Settings.from_dict()/_validate()/yaml_lite()` |
| `core.py` | 七步清洗纯函数（零 IO）＋评分/分数线门禁＋工单四档判定＋使用示例定位，每步返回台账 | `inspect_schema()/convert_types()/handle_missing()/detect_anomalies()/dedupe()/apply_custom_rules()/flag_process_limits()/validate()/score()/gate()` `workorder_tiers()/find_usage_example()` |
| `io_utils.py` | CSV/JSON 原子读写、输入指纹 | `read_csv_rows()/write_csv_rows()/write_text()/read_text()/sha256_short()` |
| `stylecheck.py` | 内置 PEP 8 子集检查（仅标准库 ast，零第三方依赖，口径与 p11_exercises 一致） | `check_file()/check_paths()/collect_sources()/summarize()` |
| `report.py` | 分节报告渲染（默认不写墙钟） | `render()/save()/now_stamp()` |
| `pipeline.py` | 编排：载入→七步→落盘→报告＋工单证据采集（PEP 8/复现/示例/重放/压测） | `run()/run_pipeline()/write_outputs()/build_sections()/peek()/run_incremental()` `collect_evidence()/reproducibility_check()/usage_evidence()/incremental_replay_check()/bench_evidence()` |

## 依赖方向
```
run.py → cli → pipeline → {core, io_utils, report, stylecheck}
cli → {config, report}        config → pipeline（经 cfg 注入，YAML 驱动）
report → io_utils             core / stylecheck：零内部依赖（core 纯函数、
                              stylecheck 只用标准库 ast），故均可独立单测
```
**规则**：下层不得反向依赖上层；`core` 不 import `io_utils`（保持可单测）；
`stylecheck` 只依赖标准库，供 `pipeline` 采集 PEP 8 证据、tests 直接复算同一口径。

## 关键质量属性
- **可测试性**：core 为纯函数 → 单测无需 mock 文件系统
- **可配置性**：阈值全部外置 YAML
- **可复现性**：种子固定于配置；`output/` 内不写墙钟（压测秒数只进 `runtime/bench.json`），
  报告头改用输入 sha256 指纹 ⇒ 跨 `PYTHONHASHSEED` 逐字节一致
