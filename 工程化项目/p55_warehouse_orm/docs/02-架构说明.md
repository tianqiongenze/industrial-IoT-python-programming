# 02 架构说明（TOGAF 四域视角）

> 项目：产线数据仓库与 ORM（SQLAlchemy 2.x + SQLite）

| TOGAF 域 | 本项目答案 |
|---|---|
| 业务架构 | 给 P4 采集数据建"仓库"：设备-测点-记录-告警四表可查可统计，支撑故障溯源，并向 P3 仪表盘交付看板数据形成闭环 |
| 数据架构 | SQLite 四表：devices 1─N points 1─N records（联合索引 idx_dev_ts），devices 1─N alarms；外键由库强制（PRAGMA foreign_keys=ON）；告警按 ts 与 records 同刻对齐以支持四表溯源；对下游契约=6 列交接 CSV（ts/device_id/line/temp/vib/status） |
| 应用架构 | models（声明式ORM）→ core（引擎/入库/查询/溯源/聚合/基准/交接）→ pipeline（编排+分层闸门+缓存策略）→ report；仓库模式：业务只调 core 函数，SQL 细节收拢在下层 |
| 技术架构 | Python 3.12 (conda pp03) + SQLAlchemy 2.1.3 + SQLite 内置；PyYAML 可选（yaml_lite 兜底）；pytest 57 项 |

## 分层与模块职责
| 模块 | 职责 | 关键接口 |
|---|---|---|
| `models.py` | 四表声明式模型 | Device/SensorPoint/Record/AlarmEvent + relationship + `__table_args__` 联合索引 + Column(comment=) |
| `core.py` | 引擎/种子/批量导入/统计查询/窗口/数据字典/字典完整性/溯源/复杂聚合/索引基准/慢查询/N+1/P3 交接/外键取证 | make_engine()/init_db()/tables_created()/seed_demo()/import_buffer()/avg_vib_per_device()/alarm_top_devices()/records_per_hour()/hourly_growth_orm()/hourly_growth_raw()/data_dictionary()/dictionary_coverage()/traceability_check()/device_hourly_summary()/device_hourly_manual()/summary_matches_sql()/index_bench()/slow_query_report()/n_plus_one_demo()/export_p3_handoff()/validate_p3_handoff()/integrity_check() |
| `pipeline.py` | 编排、墙钟隔离、分层闸门与可复现策略 | ensure_db()/query_rows()/get_bench()/_bench_view()/handoff_path()/build()/_tier_gates()/_sections()/run() |
| `config.py` | rules.yaml→Settings（yaml_lite 兜底） | load_config()/DEFAULTS |
| `io_utils.py` / `report.py` | 原子写/JSON/等宽表/报告渲染 | write_json()/fmt_table()/save() |

## 数据流（一次 run.py）
```
config/rules.yaml → ensure_db（删库重建 → seed_demo 分批提交 → import_buffer 分批提交）
   → query_rows（T4a/T4b/T4c + 窗口环比 ORM=裸SQL 双形态校验）
   → dictionary_coverage + traceability_check + n_plus_one_demo + integrity_check
   → get_bench（缓存命中读 runtime/bench.json；参数变更/--index-bench 才实测）
   → device_hourly_summary ↔ device_hourly_manual 互证
   → export_p3_handoff → validate_p3_handoff（按 P3 口径回读校验）
   → _tier_gates（D/C/B/A 逐条实测，逐级累加）→ report.txt / result.json
```

## 依赖方向
```
run.py → pipeline → core → models（SQLAlchemy 声明式）
              ↓        ↘ sqlalchemy(text/select/func/Index/event)
           io_utils ← report
              ↑
           config（YAML 驱动）
```
**规则**：下层不反向依赖上层；core 不 import pipeline；确定性证据落 output/，
墙钟实测值只落 runtime/（`pipeline.runtime_dir()`，`runtime/` 已在 .gitignore）。

## 关键质量属性
- **可测试性**：core 各函数以 engine/session 为参数并以配置驱动，测试可用 tmp_path 独立建库并只改配置证伪
- **可复现性**：随机源全部带 seed、`hash_of()` 代替内置 `hash()`、sqlite 文件先删后建；实测毫秒固化在 runtime/bench.json 缓存（详见 docs/05）
- **证据链**：外键拒绝、EXPLAIN 计划形态、N+1 的 SELECT 计数、四表溯源命中率、复杂聚合与手算互证、交接 CSV 的 P3 口径校验都是运行时真实取证，非文案
- **分层可判**：工单四档（及格/良好/优秀/超优）逐条对应可数证据，未达标即写明实测数字与补法（docs/03 §6）
