## 5. 复现验证命令（NF-1）
```bash
cd 工程化项目/p22_feature_factory
/opt/anaconda3/envs/pp03/bin/python -m pytest -q                      # 60 passed
/opt/anaconda3/envs/pp03/bin/python run.py --quiet                    # 写 output/ 与 ../runtime/timing.json
/opt/anaconda3/envs/pp03/bin/python ../verify_local.py p22_feature_factory
```
`../verify_local.py` 是工程化项目的终验脚本，对本项目跑三道闸：`pytest` 全绿、`run.py --quiet`
产出非空 `output/report.txt`、以 `PYTHONHASHSEED=1` 与 `=7` 各跑一次后比对 report.txt / result.json。
比对前它按关键字打码：含"墙钟／实测／耗时／时间戳"字样的整行、带小数的 ms 数值、以及 JSON 里
`perf`／`*_ms` 这类计时键的数值叶子都算"免比"（本轮 report.txt 免比 13 行、result.json 免比 4 项，
其中若干行是带实测数值的说明行——`output/` 内本来没有任何时长数值，所以两次运行的差异只可能
出现在这些文字行上）。因此"每个文件逐字节相同"的更强口径不靠它，而由
`python -m pytest tests/test_tier_gates.py -q` 的 12 例保证，其中
`test_output_is_byte_identical_across_two_hash_seeds` 用子进程换种子重跑并逐个文件比 sha256（不打码、
不免比），`test_measured_ms_lands_in_runtime_not_output` 与 `test_output_has_no_wallclock_values`
钉住"墙钟只写 `../runtime/timing.json`、`output/` 零时长数值"这条红线。
