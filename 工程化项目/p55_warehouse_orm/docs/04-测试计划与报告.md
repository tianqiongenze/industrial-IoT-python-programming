## 1. 测试策略
| 层级 | 方法 | 目标 |
|---|---|---|
| 单元 | pytest，每测试独立 tmp_path 建库 | 模型/查询/批量/溯源/聚合/基准/交接正常·边界·异常三档 |
| 集成 | pipeline 端到端（临时目录） | 输入→报告链路正确、产物齐全 |
| 闸门 | test_tier_gates.py 真实流水线复算 D/C/B/A | 每级判定==本次测量；只改配置即可证伪 |
| 回归+确定性 | `pytest -q` 全量；两次运行 output/ diff | 改动不破坏行为；除时间戳逐字节一致 |
| 跨项目 | 真调 p33_kpi_cockpit 的 data_source 读 P5 交接 CSV | 闭环不是口头声明（P3 不在则 skip） |

## 4. 缺陷记录
| 编号 | 描述 | 处置 |
|---|---|---|
| DEF-1 | v1.0 手写"极简 ORM"不符合工单 SQLAlchemy 要求 | v2.0 全量重构为 SQLAlchemy 2.x；ADR 更正（docs/07） |
| DEF-2 | v1.0 索引对比返回写死字符串（伪造证据） | 已改为实测耗时+EXPLAIN QUERY PLAN 真实行，无加速时如实报告 |
| DEF-3 | 种子入库用 `zip(devices * 2, points)` 指派测点：`devices * 2` 是序列重复 `[D1,D2,D3,D1,D2,D3]` 而非逐设备重复 `[D1,D1,D2,D2,…]`，映射错位使 DEV-01/DEV-02 的 vib 记录互换挂到对方测点上（T4a 计数为 164/330 而非 165/329），告警的 device_id 与记录所属测点的设备不再一致——四表溯源仅 22/57 条告警能反查到同刻读数 | 分层闸门（C 层溯源判据）抓出；改为按 relationship 回读的 `{(设备编码,指标): point_id}` 映射（core.py:141-142，注释 core.py:137-140），现溯源 57/57 命中、三处外键孤儿行 0；回归用例 test_queries.py::test_seed_records_are_on_their_own_devices_points |
| DEF-4 | A 层校验先于导出执行，首次运行报"缺全部列"（假未达标） | 调整为 export → validate 顺序（pipeline.py:192-193），并加 test_tier_gates.py::test_a_layer_is_falsifiable_by_config_only 守门 |
| DEF-5 | 实测毫秒写进 output/bench.json，导致 output/ 无法逐字节复现 | 基准缓存与基准副本库迁至 runtime/（bench.json/bench.db），B 层判据改用确定性计划形态；test_tier_gates.py TC-31/32 |
| — | 本轮无遗留缺陷 | — |
