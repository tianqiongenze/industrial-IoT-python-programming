## 1. 范围
把 P2.2 特征矩阵转化为可上线的诊断能力：sklearn 五步流（分层划分→训练→交叉验证
→GridSearch 调参→joblib 落盘）+ **F1≥0.80 硬门禁**（不达标拒绝注册）+ LR/RF/GBM
三模型对比与混淆矩阵/精确率/召回率留痕 + 接入 P5 数据仓库（新记录→抽特征→预测→
回写诊断字段）+ 标准库 ThreadingHTTPServer 推理服务（POST /predict JSON 入 JSON 出、
GET /health 真推理自检、参数/维度错 400、未知路径 404）+ 真实 HTTP 往返压测
（warmup 后看 p95/p99/QPS）+ 模型版本管理（model_v1.joblib + manifest）。
A 层 ONNX/边缘路线以导入探测如实报告可得性。所有写入只落本项目 output/。

## 4. 功能需求
| 编号 | 功能点 | 说明 | 落点 |
|---|---|---|---|
| F-01 | 数据加载 | 读课程根 P2.2 产物 features.npy/labels.npy（200×30）；缺失时文档化 seed 合成替代源并打印来源 | src/ml_service/data.py load_dataset |
| F-02 | 特征契约 | 30 维 FEATURE_NAMES 列序常量，训练/推理/联动共用；validate_feature_names 校验维数与唯一性 | data.py |
| F-03 | 五步流 | stratify 划分→LR/RF/GBM 训练→cross_val_score(cv)→GridSearchCV 留痕→最优落盘 | core.py evaluate/save_model |
| F-04 | 评估门禁 | 测试集 macro-F1≥min_f1(0.80)，不达标 RuntimeError 拒绝注册 | core.gate + pipeline 拒绝分支 |
| F-05 | 模型对比 | LR/RF/GBM/RF-tuned 同表对比（CV均值±方差、测试F1、磨损精确率/召回率） | core.build_candidates + report |
| F-06 | 混淆矩阵 | CM+per-class precision/recall+F1+classification_report 全文进报告 | core.evaluate → report.txt |
| F-07 | P5 库联动 | 拷贝 P5 warehouse.db→records 加 diagnosis 列→每设备最新窗口抽 30 维特征→预测→UPDATE 回写；feature_names 顺序校验 | bridge.py |
| F-08 | 教师包推理 | joblib 载入课程根 model_v1.joblib，校验 n_features_in_/classes_，≥10 样本推理，跨版本告警如实转录 | core.load_teacher_model + pipeline._teacher_check |
| F-09 | 推理服务 | 标准库 ThreadingHTTPServer：/predict(400 维度/JSON/非数值校验)、/health(真推理)、404 路由表、logging 落 stderr | service.create_server |
| F-10 | 性能压测 | 真实 HTTP 往返：warmup 首发 + n 次 mean/p50/p95/p99/max + QPS；首跑实测固化 bench.json，--bench 重测 | service.bench + pipeline 缓存 |
| F-11 | 版本管理 | 工件=model_v1.joblib（非匿名 model.joblib）+ manifest JSON（sklearn/numpy/python 版本、特征名清单、trained_at、指标、门禁） | pipeline.train_pipeline + core.save_model |
| F-12 | A层 ONNX | import 探测 skl2onnx/onnxruntime：装则导出+延迟对比，未装则如实报告不可得与计划 opset | onnx_export.py |
| F-13 | A层三维评价 | 工单 03-P6：LR/RF/GBM 对比在 F1 之外补「训练耗时 fit_ms + 可解释性 Top-k」——LR 取 coef_、树模型取 feature_importances_（列名=data.FEATURE_NAMES 真实列序，|值|并列按 zlib.crc32 稳定破序）；fit_ms 墙钟实测**只写 runtime/train_timing.json 不入 output/**；「分层达标」D/C/B/A 判定行进报告，tiers 进 result.json | core.top_features/evaluate(timing_out) + pipeline._tier_gates |

| NF-3 | 可配置 | 数据路径/门禁阈值/网格/CV折数/端口/压测条数/窗口长度/可解释性Top-k 20 键全在 rules.yaml 且被代码读取 | 改配置不改代码 |
| NF-4 | 可测试 | 真实断言：门禁 F1 数值、维度校验 ValueError、live HTTP 400/404、联动回写库内可查、Top-k 排序与 crc32 破并列、fit_ms 不入 output/、工单四行原文逐字回读、延迟记录两侧条数相等 | `python -m pytest -q`（55 项 / 8 文件） |

## 6. 接口约束
- CLI：`python run.py [--serve | --bench | --no-bench | --predict '<30维JSON>' |
  --link-p5 | --export-onnx] [--config CONFIG] [--outdir DIR] [--quiet]`
- HTTP：`POST /predict {"features":[30 数值]} → {"prediction","label","proba_wear","model"}`；
  `GET /health → {"status","model","n_features","sklearn","probe_predict"}`；错误→400/404 JSON
- 输出：`output/model_v1.joblib(+.manifest.json)`、`output/report.txt`、`output/result.json`、
  `output/bench.json`、`output/warehouse_diagnosis.db`；墙钟训练计时写
  `runtime/train_timing.json`（与 output/ 平级，.gitignore 忽略，不参与字节比对）
