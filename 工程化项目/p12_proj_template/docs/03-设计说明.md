# 03 设计说明

> 项目：标准工程模板生成

## 1. 模块清单与接口
| 模块 | 职责 | 关键接口（与源码逐一对应） |
|---|---|---|
| `core.py` | 模板定义 + 生成器 + 自检 + 分层事实 | `file_templates()` / `ensure()` / `verify()` / `inventory()` / `layer_facts()` / `layer_gates()` / `pre_commit_text()` / `pyproject_text()` / `requirements_dev_text()` / `resolve_scripts()` |
| `env_probe.py` | A 层闸门工具的可导入性探测 | `probe()` / `detect()` / `summary()` / `hook_coverage()` / `report_lines()` |
| `io_utils.py` | 原子写 / JSON | `write_text()` / `write_json()` |
| `report.py` | 报告渲染落盘 | `render()` / `save()` |
| `pipeline.py` | 编排与四段式证据 | `run()` |
| `cli.py` | argparse 入口（`[project.scripts]` 目标） | `build_parser()` / `main()` |

## 2. 核心算法/规则
**表驱动生成 → 读盘取证 → 分层闸门**（三步，全部零外部命令：不执行 git、不建 venv、不调检查工具）：

1. **表驱动（`core.file_templates`）**：一张 `{相对路径: 内容}` 表就是全部交付物，共 15 个文件，
   按层分工——D：`src/main.py`+`run.py`+四目录；C：`scripts/setup_venv.sh`+`.gitignore`(含 `venv/`)；
   B：`requirements.txt`/`requirements-dev.txt`（后者首行固定 `-r requirements.txt`）+`scripts/git_dev_branch.sh`；
   A：`.pre-commit-config.yaml`（`repo: local`，逐工具一个 hook，`entry` 由 `LINT_ENTRY` 映射，
   表外工具退化为 `"<tool> ."`）。工具清单/开关来自 `config/rules.yaml`：`lint_tools` 决定钩子条目，
   `emit_pre_commit=false` 则该文件根本不进表。
2. **原子落盘（`core.ensure`）**：逐文件 `os.makedirs(dirname, exist_ok=True)` 后 `newline="\n"` 写入；
   `overwrite_existing=true`（默认）时"内容不一致才重写"，因此重复运行逐字节一致且学生的手改不会被静默覆盖两次以上；
   `false` 时已存在即跳过（保留手改，读盘取证随即如实判未达标）。
3. **读盘取证（`core.verify` + `core.layer_facts`）**：不信任"我以为写出去了"，一律回读磁盘——
   `verify()` 给出 `missing/empty_dirs/junk/unexpected`；`layer_facts()` 从文件**内容**量化出事实表：
   四目录在场数、`.gitignore` 是否含 `venv/`、venv 脚本是否含 `python -m venv venv`/`pip install -r requirements.txt`/`git init`、
   两份依赖清单各自的"有效行数 / 钉了 `>=`或`==` 的行数"（`dep_lines()` 去注释、`pinned()` 忽略 `-r` 引用行）、
   dev 分支脚本是否含 `git branch dev`/`git checkout dev`/`--no-ff`、钩子文件声明的 `id` 列表（`hook_ids()`），
   以及 `[project.scripts]` 的每个 `模块:属性` 目标是否真能解析（`resolve_scripts()`：路径定位 + `ast.parse` 找顶层
   `def/class/赋值`，**不 import、不安装、不执行**，因此断裂脚手架会被当场抓到而不是留到新人第一天）。
4. **闸门判定（`core.layer_gates`）**：D=结构齐备且入口 1/1 解析；C=D 且 venv 脚本三连+`venv/` 被屏蔽；
   B=双清单 100% 钉下限且 `-r` 断链为否且分支脚本三要素齐；A=钩子文件在表内且配置要求的每个工具都有对应 hook。
   每层都可被**单条配置改动**翻掉（见 docs/04 的 `test_config_only_change_*`），从而保证"达标"是算出来的、不是写死的。
5. **诚实探测（`env_probe`）**：`importlib.util.find_spec` 判断 black/flake8/pylint/ruff/isort/pre_commit/pytest
   本机能否导入，版本取发行元数据；报告固定输出"本次运行未调用 black/flake8/pylint/pre-commit 任何命令"。
   本机课程解释器（pp03）**未安装**这些工具，故 A 层证据是"闸门文件已就位 + 探测如实上报"，绝不冒充"已格式化/已通过检查"。

6. **工单四行原文对照（`core.WO_ROW` + `core.workorder_gates()`）**：把工单《P1.2 验收标准》的
   及格/良好/优秀/超优四行**逐字**抄成常量，作为该节唯一口径来源；每行只用磁盘实物与本机真跑的
   数字判定，凡本机取不了证的子项（真开 shell 激活 conda、真联网 pip、真触发 git 钩子、CI 未产出）
   一律点名列进 `workorder_unmeasured`，**该行只写「本节取证项 通过」，绝不写「达标」**。
   它与课堂 `layer_gates` 各判各的：工单良好(C)『检查工具配置生效；pytest通过』在课堂四档里没有
   对应门禁（课堂 A 只判钩子文件声明齐，没有一处跑过生成骨架的测试），故由本节补上。
7. **生成骨架进程内真跑（`core.skeleton_smoke()`）**：临时把生成树插到 `sys.path` 首位，导入
   `src.main` 调 `main()`，再逐个调用骨架自带的 `test_` 函数，捕获断言失败；`sys.dont_write_bytecode`
   置真（不留 .pyc），退出时 `sys.path`/`sys.modules`/该标志全部原样归还。它仍是**零子进程**——
   起的只是本进程内的导入，git/venv/pip/black/flake8 一次都没调用。
8. **CI 与钩子二选一（`core._ci_workflows()`）**：工单超优行原文是『GitHub Actions CI 或 pre-commit 钩子』，
   本项目取后一支，因此如实报告 `.github/workflows` 下 CI 文件 0 个，而不是假装做过 CI。

## 3. 异常处理策略
| 异常/坏情形 | 触发场景 | 处理 | 对应测试 |
|---|---|---|---|
| FileNotFoundError | 配置文件缺失 | `load_config()` 抛出并带路径 | tests/test_config.py::test_missing_config_raises |
| 配置缺键 | rules.yaml 未写 `lint_tools`/`dev_deps` 等 | 走 `config.DEFAULTS` 兜底并在 `raw` 里可见，不静默变 None | tests/test_config.py::test_template_knobs_fall_back_to_defaults_when_absent |
| 依赖未钉下限（B 层缺陷） | `deps: - numpy` | 不抛异常：`pinned()` 算出 1/2，B 层如实判未达标 | tests/test_tier_gates.py::test_config_only_change_can_fail_layer_b |
| 钩子开关关闭（A 层缺陷） | `emit_pre_commit: false` | 钩子文件不落盘，A=False，其余层不受影响 | tests/test_tier_gates.py::test_config_only_change_can_fail_layer_a |
| 入口指向不存在的模块/属性（断裂脚手架） | `a = "src.nope:main"` | 记 `resolves=False` + 原因文本，不安装不执行 | tests/test_entrypoints.py::test_broken_target_is_reported_not_silently_passed |
| 生成文件语法坏了 | 模板被改出非法 Python | `defines_attr()` 捕获 SyntaxError 返回 False；模板自检用 `ast.parse` | tests/test_entrypoints.py::test_syntax_error_or_missing_file_is_not_resolvable、tests/test_core.py::test_main_template_is_valid_python |
| 模板外野文件 / .pyc 混入 | 手工塞文件、编译产物残留 | `verify()` 的 `unexpected`/`junk` 上报进报告（.DS_Store 类不参与 D 判定，避免无谓抖动） | tests/test_core.py::test_verify_reports_missing_empty_dir_and_junk |
| 学生手改被保留 | `overwrite_existing: false` | 内容不回滚，闸门按磁盘真实内容判未达标 | tests/test_tier_gates.py::test_overwrite_off_keeps_hand_edit_but_still_gates_on_disk |
| 空依赖/空工具集 | `deps: []`、`lint_tools: []` | 仍产出语法合法的清单与钩子文件，计数为 0 | tests/test_core.py::test_file_templates_boundary_empty_lists_still_valid |
| 可选元数据取不到 | 包存在但无发行元数据 | 版本留空字符串，`installed` 结论不受影响 | tests/test_env_probe.py::test_probe_tolerates_bad_distribution_metadata |
| 生成骨架的断言不成立 | 学生手改 `tests/test_main.py` 且 `overwrite_existing: false` | `skeleton_smoke()` 捕获异常写进 `tests_failed`，工单良好(C) 判未达标；课堂四档不受影响（它不读生成物内容） | tests/test_workorder_rows.py::test_hand_broken_generated_test_flips_workorder_c_only |
| 生成骨架导入即失败 | 模板被改出语法错误/文件被删空 | `error` 字段记异常名与消息，`tests_found=0`，工单良好(C) 判未达标，流水线不崩 | tests/test_workorder_rows.py::test_skeleton_smoke_actually_runs_the_generated_tests |
| README 正文被清空 | 手改生成树 | `readme_bytes=0`、`readme_titled=否` → 工单及格(D) 判未达标（课堂 D 只数目录与缺失，仍达标） | tests/test_workorder_rows.py::test_empty_readme_fails_workorder_d_only |
| 开发清单重复运行依赖 | `-r` 已带进 `numpy` 又写一遍 | `dep_dupes=["numpy"]` → 工单优秀(B)『requirements完整』判未达标 | tests/test_workorder_rows.py::test_duplicate_dev_requirement_breaks_restorable_claim |

## 4. 命名与代码规范
- PEP 8；`snake_case`（函数/变量）、`PascalCase`（类）、`UPPER_CASE`（常量）
- docstring 三件套：做什么 / 参数 / 返回
- 单元函数 ≤40 行，超过则拆分（`pipeline.run` 只做编排，取证逻辑一律下沉到 `core`）
- 生成物一律 `newline="\n"` + utf-8，避免跨平台字节漂移
