### 知识四要素详解（V1.2深度版·与授课PPT同源）

**B01 C→Python四映射**
- 定义：四映射=C户口迁Python：声明→动态/大括号→缩进/指针→引用/printf→f-string
- 使用场景：C老手最快上手路径——心里有C对照着学少走弯路
- 应用实例：int x=5 → x=5；printf("%d",x) → print(f'{x}')
- 扩展与误区：误区：Python变量无需声明≠无需理解类型——类型还在，只是贴在值上
- 原理：C声明才分配、Python赋值即创建；C的int定宽、Python的int无限精度；C指针手动管内存、Python引用自动回收；C数组定长、Python列表动态——四大心智迁移
- 判断依据：带着C直觉写Python会卡在'要不要先声明'——记住：赋值即声明即初始化三合一
- 逐行解释：int x;←C要先声明；x=10 ←Python一步到位；x='abc' 还能换类型（C里类型锁死）——变量=贴标签不是开盒子
- 进阶优化：Python里写struct/typedef的冲动改用dataclass；malloc/free的世界交给垃圾回收——专注业务别管内存

**B02 引用语义**
- 定义：b=a不复制货只抄门牌号——两人开同一扇门，动b就是动a
- 使用场景：函数传参/复制数据时的隐性共享——改b连a一起变
- 应用实例：b = a.copy()浅拷贝；copy.deepcopy(a)深拷贝
- 扩展与误区：误区：以为=是复制——嵌套列表必须deepcopy，浅拷贝只拷外壳
- 原理：Python变量存的是'对象的引用'（C的指针但不可做算术）：a=b不是拷贝数据而是两个名字指向同一对象——改一可见二
- 判断依据：函数传列表、两变量'同步变化'的灵异事件，九成是引用共享——浅拷贝copy()只拷第一层
- 逐行解释：b=a 两名共一物；a.append(9) 后b也多一个9；b=a.copy() 才是新列表（但嵌套的子列表仍共享）
- 进阶优化：import copy; copy.deepcopy(d)深拷贝连嵌套层全断开；is判同一对象、==判值相等——排引用问题先看is

**B03 列表扩容与字典**
- 定义：列表append=货架自动加长；字典O(1)=储物柜直取不开抽屉翻
- 使用场景：采集缓冲攒够1000条批量入库——工程节奏控制
- 应用实例：buffer.append(row)；if len(buffer)>=1000: flush()
- 扩展与误区：误区：C的malloc预分配习惯搬来——Python列表自增长已优化
- 原理：列表底层是过分配数组：预留空间摊还扩容成本，append均摊O(1)；字典是哈希表：键算哈希直达桶位，查找O(1)——选型看访问模式
- 判断依据：按下标顺序扫→列表；按键随机查→字典；既要顺序又要按键查→列表+字典索引双结构
- 逐行解释：lst.append(x) 尾部追加快（预留位）；lst.insert(0,x) 头部插入慢（全体后移O(n)）；d[key] 哈希直达——'排队'与'查档'两套物理结构
- 进阶优化：from collections import deque双端队列两头都快；字典遍历时别改键（RuntimeError），先list(d.keys())快照

**B04 try/except替代错误码**
- 定义：C层层if判错误码=快递每站验货；Python异常=坏件直接退回总站
- 使用场景：连接超时/文件缺失——错误处理集中化不污染主逻辑
- 应用实例：try: conn=connect() except TimeoutError: 重试
- 扩展与误区：误区：异常当goto滥用——只对'真异常'用，正常分支别进try
- 原理：C用返回码(-1表错)让调用方自查，Python用异常沿栈上抛直到有人接——错误处理从'每层if'变'一处兜底'
- 判断依据：文件/网络/解析三层调用，错误只在最外层try一次——中间层干净写主流程
- 逐行解释：C: if(read()<0) return -1 层层传染；Python: 最外try/except FileNotFoundError 一处接住——代码量少一半，主逻辑不掺错误分支
- 进阶优化：自定义异常类携带业务上下文（class SensorError(Exception)带dev_id）；异常链raise from保留根因

**B05 类=struct+函数**
- 定义：C的struct=数据仓库；Python类=仓库+员工——数据行为一体
- 使用场景：设备采集器封装——数据与操作不分离
- 应用实例：class Device: self.code=…; def start(self): …
- 扩展与误区：误区：类当struct用只放数据不放方法——封装价值损失一半
- 原理：C的struct只装数据、函数在外；Python的类把'数据+操作'绑一起：属性=struct字段、方法=绑定的函数——自带命名空间
- 判断依据：从C迁移心智：把'struct+配套函数组'直接翻译成类——Device{char id[8]}+start()→class Device
- 逐行解释：class Device: 属性区（self.dev_id）；方法区（def start）——比C的struct Device + void start(Device*) 少传一层指针
- 进阶优化：dataclass装饰器@dataclass自动生成__init__/__repr__——纯数据类十行变三行；具名元组轻量替代

**B06 缩进规范**
- 定义：缩进即语法块=用磅秤分装不许手掂——4空格统一禁Tab
- 使用场景：从C大括号迁来的最大习惯差异——Tab混用直接TabError
- 应用实例：PyCharm设置显示空白字符——一眼辨Tab
- 扩展与误区：误区：混用Tab与4空格本地能跑提交报错——IDE统一转换开起来
- 原理：Python用缩进表达块结构（C用花括号）：同一块必须同缩进——4空格是PEP 8军规，Tab/空格混用直接报错
- 判断依据：从C转来最容易'忘冒号'和'混Tab'——PyCharm设置Tab自动转4空格一劳永逸
- 逐行解释：if x>80: 冒号必须有；换行后4空格缩进进块——块结束=回到上一级缩进，没有end/}收尾
- 进阶优化：行太长用括号续行或\；PyCharm的Reformat Code一键规范缩进——格式问题永远交给工具
