# 02 架构说明（TOGAF 四域视角）

> 项目：模型训练与服务

| TOGAF 域 | 本项目答案 |
|---|---|
| 业务架构 | 把'跑出模型'变成'可上线服务'，并守住质量门禁 |
| 数据架构 | 特征矩阵+标签 → 训练/测试划分 → 指标 → joblib 模型文件 |
| 应用架构 | core 造数/训练/门禁/推理；pipeline 出指标+模型+自检 |
| 技术架构 | Python 3.12 + conda pp03；numpy/sklearn/joblib；pytest |

## 分层与模块职责
| 模块 | 职责 | 关键接口 |
|---|---|---|
| `core.py` | 造数/训练/门禁/推理 | `make_data()/train()/gate()/predict_one()` |
| `io_utils.py` | 模型与指标落盘 | `write_json()` |

## 依赖方向
```
run.py  →  pipeline  →  core（纯函数，零依赖）
               ↓           ↑
            io_utils ←── report
               ↑
            config（YAML 驱动）
```
**规则**：下层不得反向依赖上层；`core` 不 import `io_utils`（保持可单测）。

## 关键质量属性
- **可测试性**：core 为纯函数 → 单测无需 mock 文件系统
- **可配置性**：阈值全部外置 YAML
- **可复现性**：种子固定于配置
