# 04 测试计划与报告（GB/T 15532《计算机软件测试规范》）

> 项目：特征工厂

## 1. 测试策略
| 层级 | 方法 | 目标 |
|---|---|---|
| 单元测试 | pytest，`core` 纯函数（合成信号直接喂进 `extract`） | 覆盖正常/边界/异常三档：10/15/5 列形状与 dtype、单边谱范围、异常输入 |
| 性质测试 | `tests/test_drop_redundant.py`（真实特征矩阵探针） | 30 主特征逐名对齐、7 条恒等式、阈值含等号、优先级决定赢家、剔除后无残留冗余对 |
| 静态闸门 | `tests/test_vectorization.py`（AST + `dis` 双向对账） | 12 个特征函数逐样本循环 0 处；AST 计数＝教师版 FOR_ITER 计数；注入朴素写法必须报警并点名特征 |
| 集成测试 | pipeline 端到端（临时目录跑 `run()`，不打桩） | 输入→特征→标准化→模型→图→报告链路正确，报告数字与 result.json 一致 |
| 分层闸门 | `tests/test_tier_gates.py` | D/C/B/A 每条拿真数字；只改 rules.yaml 即可让某层判不达标（可证伪）；墙钟不入 output/；换 PYTHONHASHSEED 逐字节一致 |
| 入口回归 | `tests/test_entrypoints.py` | pyproject `[project.scripts]` 声明的 `feat_factory.cli:main` 必须解析为可调用对象；非 `--quiet` 路径退出码 0 且打印结论（`KeyError: -1` 回归闸） |
| 回归 | `pytest -q` 全量 | 任一改动不破坏既有行为；二次运行逐字节一致 |

> **计时口径的取舍**（`pipeline.measure()`）：只计 `core.extract`（数据生成／落盘／训练不计，
> 工单避坑第 3 条），重复 `perf.repeats=5` 次**取最小值**——机器噪声只会让结果偏慢，最小值是对
> "算法成本"最诚实的估计；实测毫秒只写 `../runtime/timing.json`，`output/` 内的报告与 result.json
> 一个时长数值都不出现，判定文字（"≤/＞ B 层线 100 ms"）仍逐字节可比。
> **Fisher 判别比的分母地板**（`core.fisher_ratio()`）：类内零方差的近常排列（如恒为 8/16 Hz 的
> 主频）会让分母趋 0、比值爆到 1e14 量级，故取 `max(σ0²+σ1², 1e-6×该列全样本方差)` 兜底，
> `core.near_constant()` 另给近常排列清单供复核；带地板后的实测 Top3 为
> dom_freq=30.25｜a16=21.78｜d_h2_rel=20.43（报告第 5 节）。
