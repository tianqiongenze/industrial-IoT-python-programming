## ADR-001：题1/题2/题5 用纯函数，题4 用类
- 状态：已接受（v2.0 修订）
- 决策者：项目组 + 吴工评审
- 背景：周1目标是 C→Python 语法迁移，"输入→输出"最好验证；但工单 P1.1 题4
  明确要求 `Device` 基类 + `PLC` 子类（含 scan 行为），不能全用函数。
- 备选：A 全纯函数｜B 全类｜C 按题分层混合
- 决策：**C**。题1/2/5 保持 `core` 纯函数；题4 用类且必须同时满足
  "子类新增 `scan_ms`"与"覆盖 `start()`"两点（`core.py:159/196`）；
  题3 用 `Registry` 包住字典，把"状态管理"限制在一个小类里。
- 后果：正面——纯函数单测无需 fixture，类部分则贴合工业语义；
  代价——两种风格并存，需在 docs/03 §1 用签名表消歧。

## ADR-002：设备 ID 在"配置边界"统一归一化
- 状态：已接受
- 背景：`config/rules.yaml` 写 `id: 01` 时 PyYAML 按 YAML 1.1 把它读成整数 `1`
  （八进制陷阱；`08` 反而留在字符串）。原实现用 `"02"` 查键，永远查不到，
  删除变成静默 no-op，报告还写"删除后 3 台"。
- 备选：A 配置文件全加引号｜B 代码里到处 `str()`｜C 配置边界归一化 + 单一键函数
- 决策：**C**。`config.normalize_id()`（`config.py:173`）与
  `core.normalize_id()`（`core.py:114`）规则一致，`Settings.device_key()`
  与 `Registry._key()`（`core.py:240`）是唯一构造键的出口。
- 后果：正面对策——`'01'/'02'/'03'` 全链路一致，删除必然命中；
  并要求 `exercise3` 在"删除未生效"时抛错而不是继续（`exercises.py:64`）。
  代价——两处 normalize 实现需保持同规则，已由
  `tests/test_config.py::test_normalize_id_table` 与
  `tests/test_core.py::test_normalize_id_*` 双向锁定。

## ADR-003：规范评分"能实测才输出"，缺工具就写不可用
- 状态：已接受
- 背景：工单要求 PEP 8 达标率与 pylint ≥8.5/10，但课程环境 `pp03` 未安装
  pylint/flake8/black/pre-commit（`python -m pylint --version` 实测报
  No module named pylint）。硬写一个百分比就是造假。
- 备选：A 直接写死 90%｜B 报告缺失项｜C 自研 stdlib 度量 + 真实工具探测
- 决策：**C**。`stylecheck.summarize()`（`stylecheck.py:346`）用 `ast`+`tokenize`
  实测 PEP 8 子集（W291/E101/E501/W292/F403/E999/C0103/C0116/C0114），
  并在报告里明确"非 pylint 评分"；`stylecheck.probe()`（`stylecheck.py:56`）
  逐个探测四个工具，`pylint_score()`（`stylecheck.py:70`）只在真的能跑时
  才返回分数，否则 `score=None` + 原因。
- 后果：报告可信（装上 pylint 后无需改代码即自动出真分数）；
  代价——自研规则覆盖不等于 pylint 全集，故超优(A) "pytest 全绿"也只做 ℹ 信息项，
  不替现场执行下结论。

## ADR-004：定档权威用"工单字母"，课堂跟做阶梯降级为保底自检
- 状态：已接受（v2.2）
- 背景：工单 P1.1 分层表的四行是"及格(D) ≥3题正确运行；PEP 8≥75%；有基础注释 /
  良好(C) 4题；命名有意义 / 优秀(B) 5题全对；PEP 8≥85%；结构清晰 /
  超优(A) 优秀+每题附测试用例与《迁移笔记》"；而课堂 notebook 的
  "D 学徒 / C 操作员 / B 组长 / A 师傅"阶梯把同一批要求整体上移了一档
  （它没有"良好(C)"这一层）。v2.1 之前报告沿用课堂阶梯的字母，于是出现
  "≥ C 层线 75.0%"这种与工单错位的字样，且良好(C)、超优(A) 两行实际无人判定。
- 备选：A 保留课堂阶梯字母、在文档里加注释｜B 把闸门重锚到工单字母，
  课堂跟做另立不计档的保底组｜C 删掉课堂阶梯只留工单四档
- 决策：**B**。`selfcheck.tier_gate()`（`selfcheck.py:321`）以工单四行为唯一
  定档依据，逐条输出"工单要求 + 真实测量数字 → 判定"证据行并镜像到
  `output/result.json` 的 `tiers`；课堂"D 学徒跟做"三项保留为 `FLOOR="保底"`
  伪档（`selfcheck.py:17`），不进 `TIER_ORDER`、不进 `tier_pass`，
  `tiers["保底"].counts_for_work_order=False`，报告里单列【保底】块并注明
  "保底自检（不计入工单档位）"。工单里原先没有闸门把住的三行做成可复算实测：
  命名有意义（`stylecheck.py:282`）、结构清晰（`stylecheck.py:312`）、
  每题附测试用例（`testmap.py:24`，ast 归题计数）。
- 后果：正面——档位判定与企业派发的验收口径逐字对齐，答辩可按工单行取证；
  可证伪性由配置线保证（把 `d/c/b_min_correct` 抬到 6 即让对应档判未达标，
  见 `tests/test_pipeline_cli.py::test_config_only_change_flips_that_tier`）。
  代价——同一份报告里并存"工单字母"与"课堂阶梯"两套说法，需在 README §四
  与 docs/01 §2 术语表显式解释；超优(A) 依赖优秀(B) 达标形成档位链，
  B 档任一线被改动会连带影响 A 档判定（设计上如此，已在测试里锁定）。
