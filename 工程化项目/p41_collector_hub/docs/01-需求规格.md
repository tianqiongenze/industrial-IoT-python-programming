# 01 需求规格说明（GB/T 9385《计算机软件需求规格说明规范》）

> 项目：多源数据采集中枢（03-Python程序设计-项目实战 · W06 第11次课）
> 文档版本：v1.0　编制日期：2026-10-14　密级：教学内部

## 1. 范围
三个'PLC'（本地模拟）同时说话：轮询读取 → 单位还原 → 切批 → 对账恒等式校验 → APM 计数 → 报告落盘，
并用同一份故障注入跑「不重连」「指数退避重连」「重连上限抬到吞得下最严重故障（零丢弃）」
三条链路做可靠性对照，体现'宁可慢不可丢'；前两条支撑课堂 B/C 层证据，第三条支撑工单优秀(B)。

## 3. 用户故事与验收标准
| 编号 | 用户故事 | 验收标准 |
|---|---|---|
| US-01 | 作为运维，我希望断线能退避重连 | 指数退避 |
| US-02 | 作为质量员，我希望对账不平就报错 | 恒等式校验 |
| US-03 | 作为组长，我要看到重连到底挽回多少数据 | 同一份故障注入跑两条链路，报告给出实测采集率差（91.67%→97.22%） |

## 4. 功能需求
| 编号 | 功能点 | 说明 |
|---|---|---|
| F-01 | 寄存器读取 | 可注入 transport（`transport(src, slot, attempt)`，链路中断抛 `LinkDown`） |
| F-02 | 单位还原 | ÷scale |
| F-03 | 对账恒等 | Σ批次=Σ单条 |
| F-04 | 退避重连 | 指数退避 base×2ⁿ，最多重连 retry_limit 次；用尽则计丢弃并保留已烧掉的等待耗时 |
| F-05 | APM 计数 | 计划/成功/丢弃/重试/传输调用/退避等待/模拟延迟，且自洽校验 调用=成功+丢弃+重试 |
| F-06 | 链路可靠性对照 | 同一份故障注入分别跑「不重连」与「指数退避重连」，以实测采集率差作达标证据 |
| F-07 | 分层达标 | D/C/B/A 四道闸门全部由运行期计数推出，改配置即可当场判不达标 |

## 5. 非功能需求
| ID | 类别 | 要求 | 验证方式 |
|---|---|---|---|
| NF-1 | 可复现 | 读数由 zlib.crc32 确定性生成、故障按配置表定点注入、计数全部由配置推导（不含墙钟），重复运行结果一致 | 二次运行 diff |
| NF-2 | 可移植 | 仅标准库 + 无；任意 conda 环境可跑 | 换机运行 |
| NF-3 | 可配置 | 全部阈值/清单在 config/rules.yaml | 改配置不改代码 |
| NF-4 | 可测试 | pytest 用例 ≥ 30（当前 47 例 / 4 文件），覆盖正常/边界/异常、课堂 D/C/B/A 闸门与工单四档（及格/良好/优秀/超优）逐档取证 | `pytest -q` |

## 6. 接口约束
- CLI：`python run.py [--config CONFIG] [--outdir DIR] [--quiet]`
- 配置：`config/rules.yaml`（格式见 docs/05）
- 输出：`output/report.txt`、`output/*.json`
