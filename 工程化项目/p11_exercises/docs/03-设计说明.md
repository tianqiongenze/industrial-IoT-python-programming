## 2. 核心算法/规则
- **题2 数值稳定求根**（`core.py:87`）：先算判别式 Δ=b²-4ac；Δ<0 直接 `None`。
  实根用稳定式 `q = -0.5·(b + sign(b)·√Δ)`，再 `x1 = q/a`、`x2 = c/q`，
  并按 `b` 的符号调整输出顺序，使首根仍是教科书口径的 `(-b+√Δ)/2a`。
  这样 `a=1, b=-1000000, c=1` 的极值断言残差为 0（朴素公式会有 ~1e-6 灾难性抵消）。
- **ID 归一化**（`config.py:173` 与 `core.py:114`，规则一致）：YAML 里 `id: 01`
  会被解析成整数 `1`（八进制陷阱；`08` 则留在字符串），因此配置键与代码键都
  经 `normalize_id(value, width)` 变成零填充字符串，`'01'/'02'/'03'` 全链路一致，
  杜绝"查不到 → 假装删除成功"。
- **删除有效性**（`exercises.py:64`）：`remove()` 返回 `None` 或总数未下降时
  直接抛错并让该题判 FAIL，报告必须写"删除生效"的前后计数。
- **子类覆盖**（`core.py:196`）：`PLC.start()` 调 `super().start()` 后追加
  `"%s启动, 扫描%dms"`；`scan(rounds)`（`core.py:201`）返回逐轮扫描行，
  并用配置阈值 `scan_warn_ms/scan_danger_ms` 定级。
- **工单分层达标（本项目的核心判定算法）**（`selfcheck.py:321` `tier_gate`）：
  锚定口径 = 工单 P1.1 分层表四行原文（课堂"跟做阶梯"字母上移一档，不作定档依据）。
  以"内置断言表逐题结果 + `stylecheck`/`testmap` 实测计数 + `notes.audit()` 笔记实测"
  三路证据，逐条给出 PASS/FAIL——及格(D) 3 项 / 良好(C) 2 项 / 优秀(B) 5 项 /
  超优(A) 5 项 + 1 信息项，另附不占工单字母的"保底"组 3 项。
  1. 及格(D)「≥3题正确运行；PEP 8≥75%；有基础注释」：题数线 `d_min_correct`；
     PEP 8 得分 = `stylecheck.check_paths()` 真实通过项 ÷ 检查项总数（标准库
     `ast`+`tokenize` 子集，非 pylint 评分），线值 `pep8_pass_rate_d`；
     基础注释 = `check_comments()` 数出的"有 docstring 的公开函数/模块"；
  2. 良好(C)「4题；命名有意义」：第 4 题单独判定 + 题数线
     `c_min_correct`；命名有意义 = `check_naming_meaningful()` 对生产码
     （`src/**.py` + `run.py`）公开函数/方法名的合格率（snake_case、≥2 字符、
     含元音可读、非 `tmp/foo/data1` 占位符），线值 `naming_meaningful_rate`；
  3. 优秀(B)「5题全对；PEP 8≥85%；结构清晰」：题数线 `b_min_correct` + B 档
     断言子集 + 命名规范违规数 0 + 线值 `pep8_pass_rate_b` + `check_structure()`
     的工程四件套/一题一函数（含 docstring）/src 模块 docstring 计数；
  4. 超优(A)「优秀+每题附测试用例与《迁移笔记》」：第一条证据即"优秀(B) 层
     达标"（档位依赖链，B 破则 A 破）；每题用例 = `testmap.count_per_question()`
     用 `ast` 扫 `tests/` 归题后的真实条数，线值 `tests_per_question_min`；
     笔记 = 文件存在 + 实测条数 + 逐题常见错误 5/5 + 必备章节齐全。
  每档还会印出一行汇总证据（工单原文 + 真实测量数字 + 判定），同一份内容镜像到
  `output/result.json` 的 `tiers`，报告与 JSON 逐字同源。
  超优(A) 的"pytest 全绿"仍是**信息项**（`ok=None`，报告显示 ℹ），不替现场执行下结论。

## 3. 异常处理策略
| 异常/标记 | 触发场景 | 处理 | 对应测试 |
|---|---|---|---|
| `ValueError`（`Settings.validate`） | 阈值顺序颠倒、PEP 8 分层线越界或及格(D) 线 > 优秀(B) 线、命名线越界、题数/每题用例线为负、ID 宽度/扫描上限/topk/层级非法 | 启动即拒绝，CLI 非 0 退出并打印中文原因 | `test_config.py::test_validate_rejects_bad_config`、`test_config.py::test_validate_rejects_bad_pep8_bands`、`test_pipeline_cli.py::test_cli_bad_config_is_reported`、`test_pipeline_cli.py::test_line_order_guard_rejects_impossible_band` |
| `FileNotFoundError` | `--config` 指向不存在的文件 | 抛出并提示路径 | `test_config.py::test_missing_config_raises` |
| `ExerciseError`（`core.py:26`，继承 `ValueError`） | 空输入/非数字/a=0/重复 ID/改不存在/非法 scan_ms/未启动即扫描 | 携带题号与参数上下文，最外层统一接住 | `test_core.py::test_convert_rejects_empty_input` 等 12 项 |
| 文件读取标记 | 缺失/坏编码/目录/空路径/无权限 | `safe_read()` 返回标记字符串，不崩溃 | `test_core.py::test_safe_read_*`（7 项） |
| 配置未知顶层键 | 死配置 | 记录告警并在报告首节显示 | `test_config.py::test_unknown_top_level_key_flagged_as_dead_config` |

## 4. 命名与代码规范（实测口径）
- PEP 8：4 空格、行长 ≤79、`snake_case` 函数/变量、`PascalCase` 类、`UPPER_CASE` 常量。
- docstring：模块 + 公开函数 + 公开方法齐全；`_` 前缀私有函数按 pylint 口径豁免。
- 一题一函数，`cli.main()` 只做"调用 + 输出"，业务判定不下沉到入口。
- 内置 `stylecheck` 覆盖 W291/E101/E501/W292/F403/E999/C0103/C0116/C0114，
  当前实测 **100.0%（检查项通过 4761/4761，违规 0）**，并输出逐文件 `per_file` 明细，
  见 `output/report.txt` 与 `output/result.json`。
- 命名有意义（良好(C) 证据）单独实测：生产码公开函数/方法名 **72/72 合格
  （100.0%）**，判定规则 = snake_case + ≥2 字符 + 含元音可读 + 非占位符
  （`tmp/temp/foo/bar/baz/dummy/stuff/thing/junk/data1/x1…`），私有名豁免。
