# 07 架构决策记录（ADR）

## ADR-001：评估不达标抛出门禁异常而非带病上线

- 状态：已接受（v2.0 复核维持，并落成真实代码约束）
- 日期：2026-10-14（v1）→ 2026-10-27（v2 实现补齐）
- 决策者：项目组（师傅/组长评审）

### 背景
"先上线再说"是工业事故的起点。v1.0 虽有 gate() 函数但流水线不强制其结果，
门禁形同虚设；工单 P6 要求 F1≥0.80 才可注册。

### 备选方案
A 带病上线（危险）｜B 门禁异常（硬阻断）｜C 只警告不阻断（形同虚设）

### 决策
**采用：B 门禁异常**——pipeline.train_pipeline 在 `core.gate(...) is False` 时
`raise RuntimeError("评估门禁未通过…拒绝注册上线")`（pipeline.py:44-46），
**工件不落盘、服务不起**；退出码非零可进 CI。

### 理由与证据
把"质量"变成可执行约束；test_core.py::test_gate_f1_reaches_threshold 断言真实
测试集 macro-F1≥0.80，test_pipeline.py::test_gate_hard_block 用纯噪声数据验证
gate=False→RuntimeError 的阻断路径确实存在。

### 后果
- 正面：不达标必然失败退出；阈值 min_f1 可配置（rules.yaml）。
- 代价：可能阻塞快速迭代。
- 缓解：--outdir 指临时目录做实验；报告同时打印 CV 均值±方差供趋势判断。

## ADR-002（D2）：推理服务用标准库 http.server，不引入第三方 Web 框架

- 状态：已接受
- 日期：2026-10-27
- 决策者：项目组

### 背景
课程环境（pp03）**未安装** Flask/FastAPI/Litestar/streamlit（离线不可装）；
工单 P6.2-2 原文即"http.server 实现 POST /predict"，验收口径是 curl 级调通。

### 备选方案（=工单决策矩阵三形态的代码化）
| 形态 | 延迟 | 并发 | 开发量 | 决策 |
|---|---|---|---|---|
| 脚本批处理（run.py --predict） | 无网络开销 | 无（一次一进程） | 零 | 作离线/演示通道保留 |
| HTTP 服务（http.server.ThreadingHTTPServer） | 本机往返 ~1 ms 级（实测 p95≈1.1 ms） | 线程级真并发 | 低 | **采用**（工单指定+环境可行） |
| 边缘定时任务（ONNX/小模型上边缘盒） | 端侧毫秒级、省带宽 | 单机 | 中（依赖 skl2onnx） | 教学演示：导入探测如实报告不可得 |
| 第三方框架（Flask/FastAPI/ASGI） | 相近 | 高（事件循环） | 低 | **生产替换项**：环境离线不可装，接口契约（JSON 400/404）保持一致，换框架成本局限在 service.py |

### 决策
教学实现用 **标准库 ThreadingHTTPServer**（service.py:28）：/health 真推理、
维度/JSON/非数值→400、未知路径→404、log_message→logging；sklearn 预估以
线程锁串行（预估器非线程安全）。

### 后果
- 正面：零新增依赖、测试可 port=0 起真服务真断言；与工单条文一致。
- 代价：无 keep-alive 池化/异步，高并发弱于 ASGI。
- 缓解：契约先行（请求/响应 JSON 不变），生产迁移只换 service.py 载体；
  决策矩阵已在 report.txt 呈现给 A 层讨论。
