# 01 需求规格说明（GB/T 9385《计算机软件需求规格说明规范》）

> 项目：Pandas 数据清洗管道（03-Python程序设计-项目实战 · W03 第5次课）
> 文档版本：v1.0　编制日期：2026-10-14　密级：教学内部

## 1. 范围
把单文件版清洗升级为工程化：config/core/io_utils/report/pipeline 五层单一职责、规则外置 YAML、pytest≥5（实测 33 例全绿）、口径文档化——同一任务'改规则只改1行YAML'。档位判定以《P2.1工单》验收表四行为准（v1.1 重锚，见 docs/03 §2.6）。

## 2. 术语与缩略语
| 术语 | 释义 |
|---|---|
| 工单 | 企业派发的任务单，本项目的需求来源；验收表四行即档位判定的唯一口径 |
| TOGAF 四域 | 业务/数据/应用/技术四个架构视角 |
| ABCD | 工单档位线＝《P2.1工单》「验收标准」四行原文逐字（`pipeline.WO_ROW`，报告第 15 节每档行首直接引用）：D 及格「管道完整；质量≥85%；PEP 8≥75%」/ C 良好「质量≥88%；处理日志可复现」/ B 优秀「质量≥90%；PEP 8≥85%；文档含使用示例」/ A 超优「优秀+增量处理/自定义验证规则/100万行<5分钟」；落地把四行钉成可测条件（见 docs/03 §2.6），实际线值只写在证据段，不回写原文 |

## 3. 用户故事与验收标准
| 编号 | 用户故事 | 验收标准 |
|---|---|---|
| US-01 | 作为工程师，我希望改清洗规则不改代码 | YAML 外置 |
| US-02 | 作为质量员，我希望每次清洗都有留痕 | 前后行数+分布快照 |

## 4. 功能需求
| 编号 | 功能点 | 说明 |
|---|---|---|
| F-01 | 规则外置 | YAML→清洗规则 |
| F-02 | 管道化 | config/core/io_utils/report/pipeline 五层：`run_pipeline()` 按序串七步纯函数，每步返回 `(df, audit)` |
| F-03 | 质量门禁 | 低于阈值告警 |

## 5. 非功能需求
| ID | 类别 | 要求 | 验证方式 |
|---|---|---|---|
| NF-1 | 可复现 | 固定随机种子，重复运行结果一致 | 二次运行 diff |
| NF-2 | 可移植 | 仅标准库 + pandas；任意 conda 环境可跑 | 换机运行 |
| NF-3 | 可配置 | 全部阈值/清单在 config/rules.yaml | 改配置不改代码 |
| NF-4 | 可测试 | pytest 用例 ≥ 6，覆盖正常/边界/异常 | `pytest -q` |

## 6. 接口约束
- CLI：`python run.py [--config CONFIG] [--input CSV] [--outdir DIR] [--quiet]`
  ＋模式开关 `--peek` / `--incremental` / `--no-bench` / `--stamp`（详见 docs/05 §2）
- 配置：`config/rules.yaml`（格式见 docs/05）
- 输出：`output/report.txt`、`output/*.json`

## 7. 追踪性
本规格 ↔ docs/03 设计说明 ↔ tests/ ↔ 工单任务书 三层一一对应。
