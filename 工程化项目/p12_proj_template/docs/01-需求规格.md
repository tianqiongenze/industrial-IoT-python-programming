# 01 需求规格说明（GB/T 9385《计算机软件需求规格说明规范》）

> 项目：标准工程模板生成（03-Python程序设计-项目实战 · W01 第2次课）
> 文档版本：v1.1　编制日期：2026-10-14　修订日期：2026-10-27　密级：教学内部

## 1. 范围
10 分钟内生成符合团队规范的 Python 工程骨架：**15 个文件**——src/tests/config/scripts 四目录、
.gitignore、README 三段、requirements.txt 与 requirements-dev.txt 双清单、pyproject.toml（含可用入口）、
`.pre-commit-config.yaml` 规范闸门、venv 还原与 dev 分支两支脚本；让新人第一天就按规范写代码。

## 2. 术语与缩略语
| 术语 | 释义 |
|---|---|

## 3. 用户故事与验收标准
| 编号 | 用户故事 | 验收标准（可由报告证伪） |
|---|---|---|
| US-01 | 作为组长，我希望新项目骨架统一 | 15 个文件齐备，`verify().missing==[]` |
| US-02 | 作为安全审计，我希望 .gitignore 一定在且屏蔽 venv | `layer_facts()["gitignore_venv"] is True` |

| US-04 | 作为师傅，我希望提交前被规范拦住 | 生成 `.pre-commit-config.yaml` 且逐工具声明 hook |

## 4. 工单分层需求 ↔ 实现 ↔ 证据
| 层 | 工单达标要求（教师版原表） | 本项目实现 | 报告里的证据行 |
|---|---|---|---|
| D 学徒 | 跟做示例跑通，程序出结果 | 表驱动生成 + 入口可解析 | 「D层 跟做跑通」行 |
| C 操作员 | venv 可用 + 仓库 + 结构完整 | `scripts/setup_venv.sh`、`.gitignore` 含 `venv/` | 「C层 venv+仓库」行 |
| B 组长 | 依赖可还原 + dev 分支规范合并 | `requirements.txt`/`requirements-dev.txt`（`-r` 引用+钉下限）、`scripts/git_dev_branch.sh`（`--no-ff`） | 「B层 依赖可还原+dev分支」行 |
| A 师傅 | 配置 pre-commit 钩子：commit 前自动 black+flake8 | `.pre-commit-config.yaml` + `env_probe` 真实探测可导入性 | 「A层 pre-commit 闸门」+「规范闸门环境探测」段 |

## 5. 功能需求
| 编号 | 功能点 | 说明 |
|---|---|---|
| F-01 | 模板集中 | `core.file_templates()` 表驱动 |
| F-02 | 原子生成 | `io_utils.write_text()` / `core.ensure()` |
| F-03 | 生成后自检 | `core.verify()`（missing/empty_dirs/junk/unexpected） |
| F-04 | 入口自检 | `core.resolve_scripts()` 用文件定位 + AST 校验 `模块:属性` |
| F-05 | 闸门文件生成 | `core.pre_commit_text()`，工具清单来自 `config/rules.yaml` |
| F-06 | 环境如实探测 | `env_probe.probe()/detect()/report_lines()`，未安装即写"未运行" |
| F-07 | 分层达标计算 | `core.layer_facts()/layer_gates()` + pipeline 的四行证据 |
| F-08 | 工单四行原文对照 | `core.WO_ROW` 逐字照抄工单验收标准 + `core.workorder_gates()` 按磁盘实物与进程内真跑取证，pipeline 输出「工单验收四档对照」节 |

## 6. 非功能需求
| ID | 类别 | 要求 | 验证方式 |
|---|---|---|---|
| NF-1 | 可复现 | 固定随机种子，重复运行结果一致；报告正文只允许头部一条"生成时间" | `verify_local.py` 双 PYTHONHASHSEED 比对；`test_run_is_reproducible`、`test_report_body_carries_no_extra_wall_clock_lines` |
| NF-2 | 可移植 | 仅标准库；本机无 black/flake8/pylint/pre-commit 也照常产出 | `test_env_probe.py` 全部用例 |
| NF-3 | 可配置 | 项目名/依赖/闸门工具/开关全在 config/rules.yaml | `test_config_only_change_can_fail_layer_a/b` |
| NF-4 | 可测试 | pytest 用例 ≥ 60，覆盖正常/边界/异常 | `pytest -q`（81 passed / 6 文件） |
| NF-5 | 不越权 | 测试与流水线**从不执行 git，从不创建 venv**，只校验生成文件内容 | `test_c_layer_*`、`test_b_layer_*` 仅读文本 |

## 7. 接口约束
- CLI：`python run.py [--config CONFIG] [--outdir DIR] [--quiet]`（等价于脚本入口 `proj_template.cli:main`）
- 配置：`config/rules.yaml`（键表见 docs/05，与文件逐行一致）
- 输出：`output/report.txt`、`output/result.json`、`output/skeleton/`（生成的 15 文件工程树）

本规格 ↔ docs/03 设计说明 ↔ tests/（81 条，其中 test_workorder_rows.py 14 条专司工单四行原文）↔ 工单 P1.2 任务书 四层一一对应。
