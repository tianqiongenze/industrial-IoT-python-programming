# 02 架构说明（TOGAF 四域视角）

> 项目：故障诊断模型与边缘部署（sklearn 五步流 + 标准库 HTTP 服务）

| TOGAF 域 | 本项目答案 |
|---|---|
| 业务架构 | 把"跑出模型"变成"可上线、可回滚、可审计的诊断能力"：门禁守住质量线，服务接住 MES/P7 调用，联动打通 P5 数据闭环 |
| 数据架构 | 上游 P2.2 features.npy/labels.npy（200×30，契约列序）；下游工件 model_v1.joblib+manifest、P5 库副本 warehouse_diagnosis.db（records 加 diagnosis/diagnosis_proba/diagnosis_note 三列） |
| 应用架构 | data（数据+契约）→ core（评估/门禁/落盘/教师包/可解释性 Top-k）→ service（HTTP 服务+压测）→ bridge（P5 联动）→ onnx_export（边缘路线探测）→ pipeline（编排+缓存可复现+分层达标）；模型加载一次、锁内推理 |
| 技术架构 | Python 3.12 (conda pp03) + scikit-learn 1.9.1 + numpy 2.5.3 + joblib；服务=标准库 http.server.ThreadingHTTPServer（课程环境无 Flask/streamlit，刻意零额外 Web 依赖）；PyYAML 可选（yaml_lite 兜底） |

## 分层与模块职责
| 模块 | 职责 | 关键接口 |
|---|---|---|
| `data.py` | 真实/替代数据源加载 + 30 维特征契约 | `FEATURE_NAMES`/`load_dataset()`/`validate_feature_names()`/`make_synthetic()` |
| `core.py` | 五步流评估、门禁、落盘/清单校验、教师包载入、单行预测、可解释性 Top-k | `evaluate()`（含 explain_topk/timing_out）/`top_features()`/`gate()`/`save_model()`/`load_model()`/`load_teacher_model()`/`predict_row()` |
| `service.py` | 标准库 HTTP 推理服务与真实往返压测 | `create_server()`/`serve_forever()`/`bench()` |
| `bridge.py` | P5 库拷贝→窗口抽特征→预测→回写诊断字段 | `resolve_p5_db()`/`features_from_window()`/`run_link()` |
| `onnx_export.py` | A 层边缘路线：导入探测→导出/如实报告 | `export_and_compare()` |
| `pipeline.py` | 编排：训练→门禁→工件+manifest→fit_ms 写 runtime/→教师自检→联动→压测(缓存)→ONNX→分层达标+报告 | `train_pipeline()`/`run()` |
| `config.py` | rules.yaml→Settings（20 键，yaml_lite 兜底） | `load_config()` |
| `io_utils.py` / `report.py` | 原子写/JSON/等宽表/报告渲染 | `write_json()`/`fmt_table()`/`save()` |

## 依赖方向
```
run.py → pipeline → core → data（契约）
              ├────→ service（http.server，仅标准库）
              ├────→ bridge（sqlite3 标准库 + core.predict_row）
              ├────→ onnx_export（导入探测，缺依赖不报错）
              └────→ io_utils ← report
           config（YAML 驱动，20 键全被读取）
```
**规则**：下层不反向依赖上层；core/data 不做 IO 编排；一切写入落本项目 output/
（P5 仓库只读其副本 warehouse_diagnosis.db，绝不回写 P5 原库、绝不写课程根）。

## 关键质量属性
- **可测试性**：service 以 `create_server(..., port=0)` 暴露临时端口——测试起真服务、
  发真 HTTP；bridge 以 P5 库副本工作，可 skip-guard 真实 warehouse.db
- **可复现性**：训练/划分/替代数据全带 seed；压测数字首跑实测后固化 bench.json，
  默认运行读缓存（`--no-bench` 显式声明该口径）⇒ output/ 逐字节可 diff（详见 docs/05 §5）；
  墙钟类数值（训练 fit_ms）一律不进 output/，只写 runtime/train_timing.json
- **确定性排序**：可解释性 Top-k 并列时按 `zlib.crc32(特征名)` 定序——内置 `hash()`
  受 PYTHONHASHSEED 随机化，会在 repeat 闸门下产生字节漂移（测试取证）
- **证据链**：F1/CM/GridSearch cv_results、400/404 响应体、跨版本加载告警、回写后的
  SELECT 结果、p95/QPS 都是运行时真实产物，非文案模板
