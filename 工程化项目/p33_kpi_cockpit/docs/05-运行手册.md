# 05 运行手册

## 1. 环境准备
```bash
conda create -n pp03 python=3.12 -y
conda activate pp03
pip install -r requirements.txt      # 或 requirements.lock
```

## 2. 运行
```bash
python run.py                     # 默认配置（headless 流水线，output/ 逐字节可复现）
python run.py --config config/rules.yaml
python run.py --outdir output/
python run.py --date 2026-03-01   # 单日筛选（TODO-1，与侧栏同源 core.filter_records）
python run.py --device DEV-01 --device DEV-02   # 设备多选（TODO-1，可重复）
python run.py --drill DEV-01      # A 层单设备汇总钻取（可重复，默认 config/drill.default_device）
python run.py --pdf               # 追加 reportlab 图文混排 PDF（P3.2）
python run.py --app-check         # AppTest 无头执行 app.py（不启浏览器）
python run.py --determinism       # 连跑两次比对 output/（timing.txt 除外）
streamlit run app.py              # 真仪表盘：点趋势折线点/选告警行 → 联动明细（A 层）
```

## 3. 配置说明（config/rules.yaml）
下表与 `config/rules.yaml` 逐字对齐（warn/danger 是良率百分比线，不是振动 mm/s 口径）。

| 键 | 含义 | 默认 |
|---|---|---|
| project | 项目名 | p33_kpi_cockpit |
| work_order | 工单号 | P3 |
| warn | 良率黄线（%）：低于 danger 且 ≥ warn → 黄灯；低于此 → 红灯 | 80.0 |
| danger | 良率绿线（%）＝良率目标：达到即绿灯（warn<danger 由 config 校验） | 95.0 |
| unit | 温度单位口径（c→℃/f→℉/k→K，见 config.unit_symbol） | c |
| seed | 合成数据随机种子（TODO-0 兜底路径，写入报告） | 2026 |
| topk | 异常明细/钻取榜单取前 k 条 | 5 |
| kpi.required | 工单点名的 5 个必做 KPI（总产量/平均良率/设备在线数/今日告警数/效率对标） | 5 项 |
| kpi.extra | B 层"≥7 指标"＝required(5) + extra(4) = 9（OEE均值/计划达成率/平均温度/最高振动） | 4 项 |
| thresholds.temp_max | 超过 → 异常识别命中（工单 P3.2-3） | 90.0 |
| thresholds.vib_max | 超过 → 今日告警 +1（TODO-2 c4 / TODO-4 告警表） | 4.5 |
| thresholds.status_online | 在线判定值（设备在线数 KPI） | RUN |
| targets.output_qty_per_day | 单日产量目标：效率对标分母 = 该值 × 窗口天数 | 2400 |
| targets.report_seconds_max | 工单 P3.2 时限：日报生成 < 2 分钟（pipeline 实测断言） | 120 |
| data.candidates | 按序探测的数据源候选（第一个存在且可读的即选中，来源写入报告） | ../p21_pandas_clean/output/clean.csv 等 4 项 |
| data.prefer | 期望文件名（缺失时提示语用） | clean.csv |
| data.require_columns | 最低可用列；其余列按 provenance 标注真实/派生 | [ts] |
| data.synth.* | 兜底合成参数（rows=2000、start=2026-04-01、freq=30min、devices、temp/vib/yield 区间、output_lambda=50） | 见 YAML |
| report.title | 日报标题 | 每日生产分析报告 |
| report.template | Jinja2 模板路径 | templates/daily_report.html.j2 |
| report.sections | 四段式段落名 | 生产概览/详细分析/异常识别/数据附表 |
| report.html_name / report.pdf_name | 日报产物文件名 | daily_report.html / daily_report.pdf |
| report.tail_rows | 附表层数（TODO 附表 df.tail(50)） | 50 |
| report.analysis_top | 详细分析：设备对比表最多几行 | 8 |
| report.fonts / report.cid_font | reportlab 中文字体候选 / 兜底 CID 字体 | 见 YAML / STSong-Light |
| schedule.at | 每日生成时刻 | "07:30" |
| schedule.mailto | 邮件正文链接收件人 | line-lead@example.com |
| schedule.max_wait_seconds | --schedule 演示模式最多等待秒数（离线可验证） | 5 |
| drill.default_device | --drill 未给设备时的默认值 | DEV-01 |
| drill.max_rows | A 层联动明细最多渲染行数（0 = 关掉钻取面板） | 30 |
| drill.detail_columns | 联动明细列（core.drill_rows 列裁剪） | ts, device_id, line, output, ok_qty, temp, vib, status |
| cache.ttl_seconds | @st.cache_data(ttl=...) 用（工程化要求 2） | 300 |
| lines | 产线台账（计划/产出/合格/OEE，per-line 表与 line 派生用） | 3 条产线 |

改配置不改代码示例：`drill.max_rows: 0` → A 层联动明细当场空、`result.json` 的
`tiers.A=false`、报告「分层达标」A 行改判「不达标」（tests/test_tier_gates.py 有同名闸门用例）。

## 4. 输出物
| 文件 | 内容 |
|---|---|
| output/report.txt | 完整过程报告（含「工单 TODO 覆盖」「分层达标（D/C/B/A）」「联动钻取证据（A 层·可复核）」） |
| output/result.json | 结构化结果（含 tiers、drill_link、filter_probe、linkage，供下游/答辩取数） |
| output/kpi.json | KPI 读数与红绿灯 |
| output/daily_report.html / daily_report.pdf（--pdf） | 四段式日报 |
| output/appendix.csv | 数据附表（report.tail_rows 行） |
| output/timing.txt | 唯一含墙钟实测值的文件（其余 output/ 逐字节可复现） |

## 5. 常见问题
| 现象 | 原因 | 处置 |
|---|---|---|
| `ModuleNotFoundError` | 未安装依赖 | `pip install -r requirements.txt` |
| 配置不生效 | 未传 --config | 使用默认 `config/rules.yaml` |
| 中文乱码 | 控制台编码非 utf-8 | `set PYTHONIOENCODING=utf-8` |
| 点击图表无反应 | on_select 选择事件未触发（如浏览器禁用了 JS 交互） | 确认 `streamlit run app.py` 起的是真仪表盘；离线核验用 `python run.py --app-check` |
| 测试想启浏览器 | 不允许 | 测试仅用 `streamlit.testing.v1.AppTest`（无头），禁 `streamlit run` |
